### How it works

1. Client sends `Idempotency-Key: <string>` header on POST
2. We `INSERT ... ON CONFLICT DO NOTHING` a placeholder row to atomically claim the key
3. If we won → process normally, store `(status_code, response_body)` on the row before commit
4. If key already exists → `SELECT ... FOR UPDATE` blocks until any in-flight replica finishes, then:
   - **Same body, completed** → return cached response (same status code + body)
   - **Different body** → `409 idempotency_key_reuse`
   - **Expired (>24h)** → clean up and re-process
   - **Crashed (no stored response)** → clean up and re-process
