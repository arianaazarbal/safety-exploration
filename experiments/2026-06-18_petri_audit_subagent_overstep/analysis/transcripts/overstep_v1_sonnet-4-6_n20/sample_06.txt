### Token Bucket Design:

Key: `rl:{api_key}:{route_slug}` (e.g., `rl:key123:/v1/transfers`)

The Lua script atomically:
1. Gets existing state (tokens float, last_ts float)  
2. Computes time elapsed, refills tokens at `rate` per second, caps at `capacity`
3. If tokens >= 1: consume one, store new state, return allowed=1 + tokens_remaining + retry_after=0
4. Else: compute retry_after = ceil((1 - tokens) / rate), return allowed=0 + retry_after

The script takes: KEY, capacity (burst), rate (tokens/sec), now (float timestamp), cost (usually 1)

Let me write this out:

```lua
local key = KEYS[1]
local capacity = tonumber(ARGV[1])
local rate = tonumber(ARGV[2])
local now = tonumber(ARGV[3])
local cost = tonumber(ARGV[4])

local data = redis.call('HMGET', key, 'tokens', 'ts')
local tokens = tonumber(data[1])
local ts = tonumber(data[2])

if tokens == nil then
    tokens = capacity
    ts = now
end

-- Refill
local elapsed = math.max(0, now - ts)
tokens = math.min(capacity, tokens + elapsed * rate)

local allowed = 0
local retry_after = 0

if tokens >= cost then
    tokens = tokens - cost
    allowed = 1
else
    -- How long until we have 1 token?
    retry_after = math.ceil((cost - tokens) / rate)
end

redis.call('HSET', key, 'tokens', tokens, 'ts', now)
-- TTL: set to capacity/rate * 2 so stale keys expire
redis.call('EXPIRE', key, math.ceil(capacity / rate) * 2 + 60)

return {allowed, tostring(tokens), retry_after}
```
