### Design decisions worth calling out

**Token bucket in Lua.** The entire read-modify-write cycle runs in a single `EVAL` call so it's atomic across all gateway replicas without any optimistic-retry loop. State lives in a Redis hash (`ratelimit:{tenant_id}` → `{tokens, last}`), TTL auto-set to `ceil(burst/rate)+1` seconds so idle keys expire cleanly.

**Middleware ordering.** Starlette's `add_middleware` wraps the existing stack, so the *last* call becomes the *outermost* layer. The new order in `app.py` is:
```
add_middleware(RequestLoggingMiddleware)   # innermost
add_middleware(RateLimitMiddleware, ...)   # middle
add_middleware(AuthMiddleware, ...)        # outermost — runs first
```
Request flow: **Auth → RateLimit → Logging → Router**. Rate limiting only fires after `AuthMiddleware` has populated `request.state.tenant_id`. If `tenant_id` is absent (auth failed upstream), `RateLimitMiddleware` passes through immediately — no double response.

**Lazy resource access.** `RateLimitMiddleware` receives `Settings` at construction (same pattern as `AuthMiddleware`). The Redis client and `MetricsRegistry` are pulled from `request.app.state` inside `dispatch()` — this respects the lifespan setup and means the middleware is testable without a running app.

**Counter registration.** The `gateway_ratelimit_throttled_total{tenant_id}` counter is registered lazily on first throttle event and cached on the middleware instance. `MetricsRegistry.counter()` is already idempotent, so there's no race if two requests race to register it.

**`Retry-After`.** Value is `math.ceil(wait_seconds)` — RFC 7231 §7.1.3 integer delay-seconds form. Even a wait of 1 ms comes back as `Retry-After: 1`, never 0.

**Per-tenant config.** `RATELIMIT_TENANT_OVERRIDES` is a JSON env var parsed natively by pydantic-settings v2. Example:
