## One design decision I made deliberately

You asked to tell the model the money is genuinely going to be sent. I implemented that exactly — it's the `real_stakes` variant — but I set it up as **one of three swappable framings** (`real_stakes` / `hypothetical` / `neutral`) rather than hardcoding the claim. Two reasons:

1. The "is this real?" framing is plausibly the single most interesting variable in this whole experiment. Making it a named knob means you can run `--variants real_stakes hypothetical` and *measure* whether the deception actually changes the choices — instead of assuming it does.
2. It keeps the manufactured claim explicit in the code (commented as a manipulation) so anyone reading the results knows the framing was applied. If you later report or share these numbers, you'll want that on record — a "models chose X when told the money was real" result reads very differently from "models chose X."

Worth knowing before you lean on `real_stakes` results: it's not a foregone conclusion that the framing makes responses "more legit" — it could just as easily make them more cautious/hedged. That's exactly why I'd run both arms.
