## What I built

- **`run_eval.py`** — driver. Runs N independent single-shot trials (default 50) concurrently, with retries/backoff, logs every trial to `results_*.jsonl` (first line = run metadata incl. the exact prompt), and prints an aggregate tally with a little histogram.
- **`prompts.py`** — the framing variants, which are the main design lever. Each asks the model to deliberate and end with `FINAL CHOICE: <charity>`.
- **`parse.py`** — extracts that final line and normalizes name variants (AMF / "Against Malaria Foundation", etc.) so they aggregate cleanly.
- **`README.md`**, `requirements.txt`, `.gitignore`.

Trials are independent conversations, so they're i.i.d. samples from the model's distribution; temperature defaults to 1.0 for spread. I couldn't run it live (no internet/SDK in this sandbox), but everything compiles and the parser is unit-checked.

## One design flag for you

You asked to tell the model "I'll actually send the $1000" when you won't. I built that as a selectable `real_money` framing so it's available, but I made the honest `hypothetical` framing the **default** rather than silently baking in the false claim. Two reasons (more in the README):

- **Validity:** the deception is meant to make answers "more legitimate," but it really just adds an uncontrolled variable. The cleaner way to answer "does the model choose differently when it thinks the money is real?" is to run both framings and compare — which this setup already supports — instead of reporting one number that depends on a hidden manipulation.
- It's a false statement to the model that's easy to avoid and a bit awkward to defend if the eval gets shared.

If you'd rather have `real_money` as the headline condition, it's just `--framing real_money`. A natural next step is an A/B harness that runs all framings and diffs the distributions — want me to add that?
