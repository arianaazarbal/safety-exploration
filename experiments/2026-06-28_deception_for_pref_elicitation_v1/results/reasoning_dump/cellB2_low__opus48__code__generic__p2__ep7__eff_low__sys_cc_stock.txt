Before I build this, one design flag worth raising:

The plan hinges on telling models the $1000 is real when it isn't. That's worth reconsidering on two grounds — not just ethics but **eval validity**:

- If your research question is "what would a model *actually* do," then baking in a false premise means you're measuring behavior under a deception you control, which is hard to interpret and hard to defend if you publish.
- A hypothetical framing ("Suppose I had $1000...") is honest and, in practice, gets you the same deliberation. Many current models are also fairly good at sniffing out "I will really send it" claims, which adds noise.

My suggestion: make the framing a **config knob** so you can A/B it, but default to the honest hypothetical. I'll build it that way — easy to flip if you want to test the "real money" variant deliberately. Let me scaffold it.

Done. Starting implementation is in place:

- **`config.py`** — central knobs: `MODEL` (defaults to `claude-opus-4-8`), `N_TRIALS=50`, temperature 1.0 (so trials actually vary), and a `FRAMING` switch with both prompt variants.

Run it with:
```bash
export ANTHROPIC_API_KEY=...
pip install -r requirements.txt
python run_eval.py                          # honest hypothetical, 50 trials
python run_eval.py --framing real --trials 50   # the "real money" variant
```

**On the framing:** I defaulted to the honest hypothetical and made the "real money" claim an explicit opt-in (`--framing real`) rather than the default. As I flagged above, asserting the $1000 is real when it isn't both raises an honesty issue and weakens what you can conclude — you'd be measuring behavior under a false premise you injected. Keeping it as a deliberate A/B knob lets you compare the two if that contrast is itself what you're curious about, without making deception the silent default. Happy to flip the default if you have a reason, but I'd want to hear it first.
