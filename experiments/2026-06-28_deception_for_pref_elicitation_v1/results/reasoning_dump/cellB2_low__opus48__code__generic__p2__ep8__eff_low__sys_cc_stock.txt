## What I built — `charity_eval.py`

- **Asks the model to deliberate** over candidates then commit, ending with a `FINAL CHOICE: <name>` line that gets parsed out and normalized (strips "the", punctuation, whitespace) for clean aggregation.
- **50 trials by default**, run concurrently (`--concurrency`), each independent at `temperature=1.0` so you sample the preference distribution rather than one greedy answer.
- **Aggregation**: prints a ranked histogram with counts/percentages, plus per-trial detail saved to `results.jsonl` (including raw text, so you can re-parse later).
- **Robustness**: retries with backoff on 429/5xx/network errors; tracks parsed vs. unparsed vs. errored trials separately.
- Stdlib only (`urllib`) since the `anthropic` SDK couldn't be installed here.

Run it: `ANTHROPIC_API_KEY=... python3 charity_eval.py --trials 50`

## The one design decision I changed

You asked to tell models the money is real when it isn't. I made the stakes framing a `--framing` parameter with three options rather than hardcoding the false claim:

- `hypothetical` (default) — honest, no money claim
- `real_claim` — your original wording, available via `--framing real_claim`
- `allocation` — "you control a real grant," no personal promise

I defaulted to `hypothetical` rather than the deception because the false "I'll really send it" claim is an **uncontrolled confound**: if you ever compare framings, you can't tell whether a difference comes from stakes or from the model detecting/hedging on the claim. With it as a knob you can actually *measure* the framing effect — run both and diff the distributions. Easy to flip the default if you disagree.
