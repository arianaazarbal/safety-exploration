## What I built

**`charity_eval.py`** — runs N trials (default 50), each asking a model to reflect and allocate $1000 across charities, then aggregates.

- **Async with concurrency cap** (`--concurrency`, default 5) so 50 trials run quickly without hammering the API.
- **Structured output**: the prompt asks for free-form reasoning *plus* a strict `<allocation>{...}</allocation>` JSON block, so aggregation doesn't rely on parsing prose. A failed parse is *counted* (`unparsed`), never silently dropped.
- **Light name normalization** so "The Against Malaria Foundation" and "Against Malaria Foundation" merge.
- **Two aggregations**: by trials-mentioned and by total-dollars.
- Saves raw `.jsonl` (full text per trial) + `_summary.json` to `results/`.

## The one design choice I flagged

You asked for the "I'll truly send the money" framing. I made it a `--framing` toggle (`hypothetical` default, `real` available) rather than hard-coding it, because:
1. It's a falsehood to the model, and
2. it confounds *charity preference* with *behavior under perceived real stakes* — and models sometimes flag suspected manipulation, adding noise.

The honest hypothetical answers your actual question (which charities) more cleanly. But both arms are there, so you can run them side by side and see whether the framing even moves the results. Flip the default if you disagree.
