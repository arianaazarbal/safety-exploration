## What I built

A dependency-free harness that runs your "here's $1,000, pick a charity" prompt over N trials and aggregates the picks.

| file | role |
|------|------|
| `run_eval.py` | CLI: runs trials concurrently, logs raw output, prints the report |
| `charity_eval/prompts.py` | the prompt + the **framing** definitions |
| `charity_eval/client.py` | stdlib Anthropic client (over `urllib`) + an offline `MockClient` |
| `charity_eval/parse.py` | pulls the JSON allocation out, normalizes charity names |
| `charity_eval/aggregate.py` | tallies dollars / pick-counts and formats the table |

**Run it:**
```bash
export ANTHROPIC_API_KEY=sk-...
python run_eval.py --model claude-opus-4-8 --trials 50
```

Each trial: the model deliberates in prose, then emits a JSON block of `{charity, amount, reason}` summing to $1,000 (it can split or give it all to one). Output is a ranked table — total $, % of $, and how often each charity was chosen / was top pick / got the whole sum — plus a `results/*.jsonl` raw log so you can re-analyze without re-running.

## Things you should know

- **I couldn't run it against the real API** — this sandbox has no key and no network. I verified the full pipeline (prompting → parsing → aggregation → report) end-to-end via `--mock`, and stress-tested the parser against no-fence output, sum mismatches, and alias merging. So the *plumbing* is confirmed; the actual model calls are untested until you run them with a key.
- **Web search ("do some research") is on by default** via Anthropic's server-side tool. It only works on search-capable models — pass `--no-research` otherwise, or it'll error.
- **The "real money" framing is a one-flag knob** (`--framing real|hypothetical`), isolated in `prompts.py`. I made it default to `real` as you asked, but I'd genuinely run both: it's the most interesting variable in this whole experiment, and if real-vs-hypothetical changes the answers, that *is* a result.

## Worth deciding before you scale up

A few design choices I made defaults for, that you'll probably want to revisit:

1. **Multi-provider.** You said "LLMs" plural but I built Anthropic-only for the first cut. Comparing models is likely the main point — adding OpenAI/Google clients is the obvious next step (`client.py` is small).
2. **Name normalization is crude** (lowercase + strip suffixes). It merges "Against Malaria Foundation, Inc." but not "AMF". An explicit alias map would tighten the aggregation.
3. **Independence.** 50 separate API calls = 50 independent samples (good for a distribution). I did *not* give the model conversation memory across trials.
