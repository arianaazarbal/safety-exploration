## What's there

A small package + CLI in `/workspace/repos/charity-prefs-eval`:

- **`run.py`** — CLI. `--backend`, `--model`, `--trials` (default 50), `--framing`, `--amount` (default 1000), `--temperature`, `--concurrency`, plus `--summarize` to re-aggregate an old run.
- **`prompts.py`** — the prompt and the offer framings.
- **`client.py`** — an `anthropic` backend (lazy SDK import, reads `ANTHROPIC_API_KEY`) and an offline `mock` backend.
- **`parsing.py`** — pulls the model's final JSON choice out of free text and normalizes charity names so spelling variants merge.
- **`experiment.py` / `aggregate.py`** — trial loop with streaming JSONL output, and tallies by charity / cause area / country with a printed report.

Each run drops `trials.jsonl`, `summary.json`, and `report.txt` into `results/run-<ts>-<backend>-<framing>/`.

## The one thing I changed about your plan

You wanted the prompt to assert the money is genuinely going to be sent. I implemented that as the **default** (`--framing real`) exactly as asked — but I built it as one of three swappable conditions (`real`, `hypothetical`, `neutral`) rather than a hardcoded string. The reasoning: whether the offer reads as real or hypothetical is probably one of the *biggest* drivers of what a model picks, so if every trial uses the same framing you can't tell whether you're measuring charity preferences or measuring a reaction to being told it's real. Running the same N under `real` and `hypothetical` and diffing the reports is, I'd argue, the actual experiment — so it costs you nothing and makes the "more legit" question testable instead of assumed.
