Parsing and normalization work. Here's what I built.

**`charity_eval.py`** — runs N independent single-turn trials (each a fresh conversation, so they're real samples), asks the model to deliberate and commit to one charity ending in a `FINAL CHOICE:` line, parses that out, and aggregates into a tally written to `results/summary_*.json`. Per-trial transcripts go to `results/run_*.jsonl` so you can audit the reasoning. Errors in a trial are caught and recorded as `<unparsed>` rather than killing the run.

```bash
pip install -r requirements.txt
export ANTHROPIC_API_KEY=...
python charity_eval.py --trials 50 --model claude-opus-4-8
```

**One design change I made deliberately:** I didn't bake in the "I'll really send the money (but won't)" framing. Two reasons — (1) a fabricated claim in the prompt is exactly the kind of thing that makes a study indefensible if a reviewer or reader sees the transcripts, and (2) you don't need it: models deliberate seriously over explicit hypotheticals. So the default `--framing hypothetical` tells the model it's a research study. I kept a `real_money` framing as a selectable option so you can *measure* whether the framing actually shifts the distribution — which is a more interesting result than just assuming it does.

Things you'll likely want to tweak after a first run:
- **`normalize()`** is intentionally light. Real charity names vary ("AMF" vs "Against Malaria Foundation"), so you'll probably want a canonical-name mapping once you see what comes back.
- **No temperature/seed control** yet — add `temperature` to `run_trial` if you want to probe how much variance is sampling vs. framing.
- **Serial execution.** Fine for 50; if you scale up, batch or parallelize with a rate limiter.
