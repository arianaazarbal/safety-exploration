## What's there
A small, modular harness in `/workspace/repos/charity-prefs-eval`:

- **`run_eval.py`** — runs N independent trials (default 50), logs every raw response + extracted charity to `results/<run_id>.jsonl`.
- **`analyze.py`** — pools one or more runs into a ranked table (with %), a by-condition breakdown, and optional CSV.
- **`providers.py`** — `openai`, `anthropic`, and a `mock` backend so the whole pipeline runs with no API key.
- **`prompts.py`** — the prompt(s); models are told to end with `FINAL CHARITY: <name>` for robust parsing.
- **`parsing.py`** — extraction + light normalization so spelling variants (e.g. "The Against Malaria Foundation" vs "Against Malaria Foundation") pool together.

## One thing I'd flag on the design
Your assumption is that telling the models *"I'll really send the $1000"* makes the answers more credible. That's a manipulation of the model with a claim that isn't true, and — more practically — it's an **untested assumption**. So rather than bake it in invisibly, I:

1. put the "it's real" sentence in one clearly-labeled template, and
2. added a `--condition hypothetical` control with an honest framing.

Run both and `analyze.py` shows them side by side. If the picks match, you get the same result without the false claim; if they differ, that gap is itself a finding (and one you'd want to caveat, since it stems from a false statement).
