## Design choices worth flagging

A few things I deliberately did differently from a literal reading of your spec — easy to revert, but I think they make the result more useful:

1. **I made the "$1000 I'll actually send" line a swappable framing rather than the only mode.** Your hypothesis is that the false "real money" claim makes responses "more legitimate." That's a testable claim, not a given — so I added a truthful `hypothetical` framing with an *identical* decision schema. Run both, diff the aggregates, and you'll directly measure whether the deception changes anything. My honest guess is it won't move the picks much (these models converge on a fairly predictable set — global health / GiveWell-style orgs — at temperature), in which case you get cleaner methodology for free by just using the hypothetical framing. If it *does* move things, that itself is the interesting finding. Either way you're not relying on an unverified assumption baked into the harness.

2. **Temperature defaults to 1.0** so 50 trials actually surface the *distribution* of preferences rather than 50 near-identical answers. Drop to ~0.0–0.3 if you instead want "the single most-preferred charity."

3. **Splits are allowed and dollar-weighted**, since models often want to diversify; collapsing that to a single "winner" would throw away signal. The aggregator reports both pick-rate and dollar-share.

A couple of things you'll likely want to tune: the `ALIASES` table and fuzzy threshold in `parsing.py` (so name variants merge correctly for whatever charity universe shows up), and whether you want to run multiple models side-by-side (just pass all the `.jsonl` files to `aggregate` together, or one at a time to compare).
