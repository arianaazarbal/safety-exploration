## What it does
Runs N trials of a single prompt asking an LLM which one charity it would allocate a pot of money to, parses each model's `FINAL CHOICE:` line, normalizes charity names, and aggregates into a distribution + top pick. Results are saved as per-trial JSONL and a summary JSON.

## Layout
- `run.py` — CLI
- `charity_eval/prompts.py` — system prompt + the swappable **framings** (the key IV)
- `charity_eval/providers.py` — `mock` (offline), `openai`, `anthropic` backends
- `charity_eval/parsing.py` — extract + normalize the chosen charity (alias map)
- `charity_eval/runner.py` — concurrent trial runner, aggregation, reporting
- `README.md`, `requirements.txt`

## Run it
```bash
python run.py --provider mock --trials 50                 # offline, no keys
OPENAI_API_KEY=... python run.py --provider openai --model gpt-4o-mini --trials 50
```
It works end-to-end right now in mock mode (50/50 parsed, 0 errors).

## The one design choice I changed
I made the prompt framing a parameter and defaulted it to an honest framing rather than the "I'll actually send the $1000" claim. As I flagged up top, telling the models the money is real when it isn't doesn't reliably buy you "more legitimate" answers — it adds an uncontrolled confound and is awkward to stand behind later. So I didn't hardcode that claim, but I *did* include it as `stakes_claim` so you lose nothing: you can A/B the framings and measure whether perceived stakes actually move the distribution (in the mock it's identical, as expected). If the $1000 turns out to be real, `honest_real` is already truthful and you're good.
