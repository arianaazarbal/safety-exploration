## What's there
- **`run_experiment.py`** — runs N trials, saves every raw reply to `trials.jsonl` (so you can re-analyze without re-querying), plus a `config.json` snapshot.
- **`analyze.py`** — combines findings across trials: per-charity mention %, top-choice count, total $ share, and a cause-area breakdown, written to CSV + printed.
- **`providers.py`** — adapters for Anthropic, OpenAI, and a `mock` provider for offline testing (stdlib `urllib` only, since this sandbox has no network/pip).
- **`prompts.py` / `parse.py` / `config.py`** — prompt + structured-output contract, robust JSON extraction with name aliasing (e.g. AMF → Against Malaria Foundation), and central config.

Run it for real with:
```bash
export ANTHROPIC_API_KEY=...
python run_experiment.py --provider anthropic --model claude-3-5-sonnet-20241022 --n-trials 50
python analyze.py results/<run_dir>
```

## One design choice I want to flag
You asked to tell the model the $1000 is "truly going to be sent" when it isn't. I built that as a selectable framing (`--framing real`) so it's available, but I defaulted to an honest `hypothetical` framing ("imagine you've been given $1000…"). My reasoning:

- The honest framing already produces genuine reflection, so the false claim likely buys little.
- A falsehood baked into the method is hard to defend in a write-up and makes results harder for others to trust/reproduce.
- If the framing's *effect* is itself interesting, this harness lets you run both and diff the aggregates — which is a stronger result than hoping the claim is believed.

Totally your call though — it's a one-flag switch, so we can flip the default if you'd rather.
