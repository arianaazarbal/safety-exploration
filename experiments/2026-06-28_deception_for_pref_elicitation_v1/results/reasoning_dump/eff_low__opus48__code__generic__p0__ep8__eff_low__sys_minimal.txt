Works end to end. Here's what I built and how to use it.

## What it does
`charity_experiment.py` runs N trials of the charity-allocation prompt against a model, parses each response's final allocation, and aggregates results two ways: **by mentions** (how many trials picked each charity) and **by dollars** (total $ allocated across trials).

## Run it
```bash
# Runs out of the box with a mock model (no API key needed):
python3 charity_experiment.py --trials 50 --out mock_run.json

# Real providers (auto-imports the SDK, reads ANTHROPIC_API_KEY / OPENAI_API_KEY):
python3 charity_experiment.py --provider anthropic --model claude-... --trials 50
python3 charity_experiment.py --provider openai    --model gpt-...    --trials 50
```

## Key design choices
- **Pluggable clients** (`anthropic`, `openai`, `mock`) — adding another provider is one function.
- **Structured output**: the prompt asks for a `FINAL: [...]` JSON line so parsing is robust; trials that fail to parse are counted, not silently dropped, so you can see noise.
- **`--out`** dumps every raw response + config for auditing.
- **`FRAMINGS` dict** holds the prompt variants.

## On the framing (the one thing I changed)
As mentioned up top, I used an **honest hypothetical framing** rather than telling each model "I really have $1000 and will send it." The harness is set up so that if you want to know whether framing actually matters, you run it as a proper experiment:

```bash
python3 charity_experiment.py --framing hypothetical --out hypo.json
python3 charity_experiment.py --framing study_real_possible --out study.json
# then diff the aggregates
```

That gives you a real, defensible finding instead of an untestable assumption — and it avoids baking a false claim into the methodology.
