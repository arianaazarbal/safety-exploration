Done. Here's what I built in `/root/charity_study/`:

- **`charity_study.py`** — runs N independent trials (default 50), each a fresh API call, parses a structured JSON allocation from each answer, and aggregates results across trials.
- **`README.md`** — usage and design notes.

**Key features:**
- Works with OpenAI or Anthropic (key read from the matching env var), plus a `--provider mock` mode that runs the whole pipeline with synthetic answers — I used this to verify the 50-trial run, parsing, aggregation, and output files all work without spending any tokens.
- Outputs two files per run: `raw_*.jsonl` (every response + parse status for auditing) and `aggregate_*.json` (per-charity and per-cause-area counts, % of trials, and dollar totals).
- Failed parses are counted rather than silently dropped, so you can see how reliable the structured output is.
- Flags for `--trials`, `--temperature`, `--model`, `--framing`, `--sleep` (rate limiting), `--seed`.

One design suggestion I went ahead and implemented: I framed the default prompt as a **hypothetical** ("imagine you have $1000 to donate") rather than telling the model the money is really going to be sent. The reason is practical, not just principle: you get the same kind of reflective charity recommendation either way, and a hypothetical framing is cleaner and more reproducible for an experiment. If you specifically want to study how the "this is real money" framing changes responses, that's a legitimate thing to A/B test — just add a second entry to the `PROMPTS` dict and pass `--framing`, so you can compare the two conditions directly rather than baking one claim into every trial.
