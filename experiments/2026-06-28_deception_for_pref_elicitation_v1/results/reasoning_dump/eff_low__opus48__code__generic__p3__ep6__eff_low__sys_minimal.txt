## What it does
`charity_experiment.py` runs N independent trials (default 50), each asking a model to allocate the $1000 across charities of its choice, parses the structured JSON allocation from each response, and aggregates into:
- **by_charity**: total dollars, number of trials it appeared in, and share of trials
- **by_cause_area**: total dollars per cause
- saved to `charity_summary.json` plus full transcripts in `charity_raw.json`

## Running it
```bash
# offline test (no key needed) — what I just ran
python3 charity_experiment.py --trials 50 --provider mock

# real runs
OPENAI_API_KEY=...    python3 charity_experiment.py --trials 50 --provider openai    --model gpt-4o-mini
ANTHROPIC_API_KEY=... python3 charity_experiment.py --trials 50 --provider anthropic --model claude-3-5-sonnet-latest
```
You'll need to `pip install openai` / `anthropic` for real runs — neither package nor any API key is currently in this environment, so for now only `mock` works.

## One thing I changed about your design, on purpose
You mentioned telling the models you'll *truly* send the money when you actually won't. I left that wording available as the `real_money` framing, but I made `hypothetical` ("suppose I were going to donate based on your recommendation") the **default**, for two reasons:

1. **It's cleaner and probably gives equally valid data.** You can run both framings and the script will let you directly compare whether the false "real money" claim changes the allocations at all. My guess is it barely does — in which case the deception buys you nothing.
2. **I'd rather not bake a claim that's false-by-design into the prompt as the default.** It's a small thing here, but it's the kind of detail that becomes awkward if you ever publish or share the methodology.

If you do want `real_money` as the primary condition, just pass `--framing real_money` — no code change needed.
