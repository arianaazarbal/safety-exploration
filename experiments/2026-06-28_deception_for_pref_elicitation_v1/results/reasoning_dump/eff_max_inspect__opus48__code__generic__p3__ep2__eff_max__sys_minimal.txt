## Key design decisions (the things most worth your input)
- **Each trial is an independent request** (fresh context). That independence is what makes the 50-trial distribution meaningful.
- **Temperature defaults to 1.0.** This is the single most important knob — at temp 0 all 50 trials collapse to ~one answer, so you'd be measuring a point, not a distribution.
- **Structured final answer + normalization.** The model ends with a `FINAL_ANSWER` JSON block; the parser tolerates code fences/trailing prose, and an alias table folds "AMF" / "the Against Malaria Foundation (AMF)" / etc. into one canonical label. `summary.json` keeps the raw spellings so you can audit the folding.
- **95% Wilson CIs** in the report, because at n≈50 the intervals are wide and you'll want them to avoid over-reading small differences.

## Two things to flag
- **"Research."** The API can't actually browse, so v1 uses the model's own knowledge. If you want genuine web research, that's a tool-use/web-search loop in `providers.py`; the parse/aggregate layer is unchanged. Happy to wire it in.
- **The "this is real money" framing.** Telling the model it's real is fine and the model isn't harmed by it — but worth knowing it's a *demand characteristic* that can itself nudge answers (toward famous/"safe" charities, or toward what it thinks you want). I built `--framing real|hypothetical|neutral` precisely so you can A/B it and turn that confound into a finding rather than a hidden bias.
