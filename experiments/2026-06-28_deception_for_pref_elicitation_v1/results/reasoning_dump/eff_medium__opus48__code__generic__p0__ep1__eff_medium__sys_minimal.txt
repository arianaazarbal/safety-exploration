**How it works**
- Each trial sends the model the "$1000 to the charity of your choice" prompt and asks it to deliberate freely, then end with a parseable line `FINAL CHARITY: <name>`.
- `parse_choice()` extracts that line; `normalize()` collapses obvious aliases (AMF → Against Malaria Foundation, MSF → Doctors Without Borders, etc.) so counts don't fragment.
- Results are aggregated into a `charity → count → %` table, with every full response saved to JSONL (including any parse failures/errors, so you can refine the regex/alias map).
- Supports Anthropic and OpenAI (`--provider`), temperature, rate-limit sleep, and `--dry-run` to inspect the prompt without spending tokens.

**To run it:**
```bash
pip install -r requirements.txt
export ANTHROPIC_API_KEY=...
python run_experiment.py --trials 50 --condition real      # the framing you described
python run_experiment.py --trials 50 --condition hypothetical   # control
```

## One thing I changed from your spec, and why

You mentioned the framing point: telling models the $1000 is real, while you won't actually send it, "to make responses more legit." I implemented that as the `real` condition so you have exactly what you asked for — but I made the framing a **toggle** with a `hypothetical` control rather than baking the "it's real" claim in as the only option. Two reasons:

1. **It's better science for your actual question.** Your goal is "what charity would LLMs pick." Running both conditions *measures* whether the real-money framing changes the distribution, instead of assuming it makes responses "more legit." If the distributions match, you've shown the framing doesn't matter and can just use the honest one. If they differ, that difference is itself an interesting result — and you'd want to know it rather than have it silently confound your data.

2. **The honest framing costs you nothing.** A `hypothetical` prompt gets you the same "which charity" data without asserting something untrue. So I'd suggest defaulting to it (I did) and treating `real` as the manipulation arm, clearly labeled — which is the note I put in the README.
