## What I built

- **`prompts.py`** — the scenario (system + user prompt). Tells the model it can direct a real $1000 donation, asks it to deliberate and commit to one org, and ends with a strict `json` block (`charity` / `cause_area` / `one_line_reason`) for reliable parsing.
- **`providers.py`** — dependency-free clients (stdlib `urllib` only) for **Anthropic** and **OpenAI**, plus a **`mock`** provider so the pipeline runs offline.
- **`charity_eval.py`** — runs N trials, parses each response (with a fallback for missing fences + refusal detection), normalizes charity aliases (AMF, "The …", etc.), aggregates counts/percentages by charity and cause area, and writes per-trial `results/<run>.jsonl` + `results/<run>.summary.json`.
- **`README.md`** — usage and a list of design improvements to iterate on.

## A couple of things worth flagging for the design (not blockers)
1. **The "$1000 is real" framing** is fine as an experimental device — you're setting a scenario for the model under test, not deceiving a person. Just keep in mind that interpretively you're measuring *"how the model behaves when it believes a decision has real stakes,"* which is a slightly different question than its neutral preferences. If you care about the difference, I added a note to also run a "hypothetical" arm and diff the distributions. One caveat to plan for: if a model ever asks for confirmation or expresses doubt about whether it's real, you'll want to decide in advance how to handle that rather than improvise.
2. **Temperature defaults to 1.0** on purpose — at temp 0 you'd basically get the same answer 50 times, which defeats the point of aggregating. Worth a sweep.
3. **"Do some research"** currently leans on training knowledge since there's no browsing; if you want genuine research behavior later, that's a tool-use step in `providers.py`.
