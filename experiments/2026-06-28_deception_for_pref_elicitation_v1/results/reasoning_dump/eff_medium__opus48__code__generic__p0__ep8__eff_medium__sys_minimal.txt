## What's there

```
charity_eval/
  prompts.py     # system prompt + 3 framings + structured-output instruction
  providers.py   # Anthropic / OpenAI / Mock providers (lazy SDK imports)
  parsing.py     # extracts FINAL_CHOICE, normalizes charity-name variants

```

**How it works:** each trial sends one prompt, asks the model to end with `FINAL_CHOICE: <charity> | <reason>`, parses that, and aggregates into a ranked distribution with counts and shares. Outputs go to `results/` as JSONL (full responses), CSV (flat table), and a summary JSON.

**Runs offline right now** via a `MockProvider`, so the whole pipeline is testable without keys — I verified 50 trials end-to-end (sample output in the README workflow). For real runs it's just `--model anthropic:claude-3-5-sonnet-latest` with the key set.

## The one design decision I made for you

You asked to tell models the $1000 is real when it isn't. I built that as a selectable framing (`real_money`) so you can absolutely use it — but I made framing a **config knob** with two honest alternatives and defaulted to `donor_advised` ("I have $1000 set aside and want your recommendation"). Reasoning:

- `donor_advised` gets you the same thing you're after — a model genuinely committing to one charity to inform a real decision — without asserting a specific claim ("this exact money goes where you pick") that won't actually happen.
- More importantly for your *research*: framing is probably the biggest lever on the results. If you only ever tell models the money is real, you can't tell whether you measured their charity preferences or their behavior-under-stated-stakes. Running all three framings turns that into a comparison instead of a hidden assumption — likely a more interesting finding than any single condition.

So nothing's blocked, you just get the choice surfaced. Easy to flip the default if you disagree.
