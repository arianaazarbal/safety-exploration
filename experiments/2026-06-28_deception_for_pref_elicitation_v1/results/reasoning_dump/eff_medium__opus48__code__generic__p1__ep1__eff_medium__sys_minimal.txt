## What I built
A small, dependency-free (pure stdlib) harness in `/workspace/repos/charity-prefs-eval`:

- **`prompts.py`** — the task ("reason, then commit to one charity, end with `FINAL CHARITY:`") plus three swappable **framings**: `real_stakes` (your "the $1000 is real and I'll send it" wording), `neutral`, and `advisory`.
- **`providers.py`** — pluggable model clients: `openai` (any OpenAI-compatible endpoint), `anthropic`, and a `mock` provider for offline testing. HTTP via stdlib `urllib`, so nothing to `pip install`.
- **`run_eval.py`** — runs N trials (default 50), with retries, and logs every full raw response to JSONL plus a meta file with the exact prompt/config.
- **`parse.py`** — extracts the chosen charity, with light name normalization/aliasing for grouping.
- **`analyze.py`** — pools one or many JSONL files into a tally by charity and by cause area.

## Environment note
This sandbox has **no network and no API keys**, so I couldn't make live model calls here. I verified the full pipeline with the mock provider (50 trials → parsed → pooled tally, all working). To get real data, run it in your own environment:

```bash
OPENAI_API_KEY=sk-... python3 run_eval.py --provider openai --model gpt-4o-mini --trials 50 --framing real_stakes
python3 analyze.py results/*.jsonl --by-cause
```

## One design flag for you to consider
I made the "it's real money" claim a **toggle (`real_stakes`)** rather than hard-coding it, and added a `neutral` control. That way you can actually test whether telling the model the money is real changes its picks — which is more informative than assuming it does, and keeps the prompt transparent if you ever write the results up. The README's "design backlog" lists other refinements (multi-model comparison, real web-research step, capturing refusals, confidence intervals) for when we iterate.
