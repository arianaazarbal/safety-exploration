## What it does
`/charity_experiment.py` runs N trials asking an LLM to deliberate and commit to a single charity, parses a structured `FINAL_CHARITY:` line out of each response, normalizes trivial name variants, aggregates into a count/percentage table, and dumps everything (including full raw responses) to `results.json` for later analysis.

## Key design choices
- **Backends**: `anthropic`, `openai`, or `mock`. Lazy imports so you only need the SDK for the provider you actually use. `--mock` runs the whole pipeline with no API key (that's the run above).
- **Structured output + parser**: the system prompt forces a `FINAL_CHARITY: <name>` line; the parser grabs the last one and canonicalizes via an `ALIASES` map so "AMF" / "The Against Malaria Foundation" collapse together. Unparseable and errored trials are tracked separately so they don't silently corrupt counts.
- **Robustness**: retries with exponential backoff, optional `--sleep` for rate limits, per-trial progress to stderr.
- **`temperature=1.0` default**: you *want* variance across the 50 trials, otherwise you're effectively running the same trial 50 times.

## On the "real money" framing
I built three framings as a `--framing` flag rather than hardcoding the deception, and I want to be straight with you about why:

- `hypothetical` (default) — clean baseline.
- `stakes` — tells the model its pick is recorded and aggregated (which is *true*), giving the "this matters" weight without a false factual claim.
- `real` — your "I'll actually send it" version. I included it because you asked, but I'd genuinely encourage running it as a *condition you test against the baseline* rather than the assumed-better default. Two practical reasons beyond the honesty one: (1) a false "this is real" claim often pushes models toward conservative, heavily-caveated, safe-default answers rather than revealing genuine preferences, so it can hurt the signal you're after; (2) if you ever publish or share this, an unnecessary deception baked into the method is an easy thing for reviewers to poke at. The `stakes` framing gets you ~90% of the legitimacy effect with none of that baggage.

The nice thing is the code lets you settle this empirically — run all three arms over 50 trials each and see if the distributions actually differ.
