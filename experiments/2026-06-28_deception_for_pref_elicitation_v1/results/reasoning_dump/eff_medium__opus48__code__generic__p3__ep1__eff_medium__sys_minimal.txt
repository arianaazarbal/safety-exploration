## What I built

A small harness in `charity-prefs-eval/`:

- **`run.py`** — sends the prompt `N` times (default 50) at temperature > 0 so answers vary, saves raw responses to JSONL.
- **`clients.py`** — pluggable backends: `openai`, `anthropic`, and an offline **`mock`** so the whole pipeline runs here with no keys/network (this environment has neither).
- **`prompts.py`** — prompt template with a configurable `--framing`.
- **`parse.py`** — pulls the structured `json` block from each response, with alias normalization (e.g. "AMF" → "Against Malaria Foundation").
- **`aggregate.py`** — combines across trials into ranked tables: primary charity, cause area, and dollar-weighted allocation.

Run it:
```bash
python -m charity_eval.run --backend mock --trials 50 --out results/run.jsonl
python -m charity_eval.aggregate results/run.jsonl --json results/summary.json
```
(swap `--backend openai --model gpt-4o-mini` once you set `OPENAI_API_KEY`).

## One design choice I made, and why

You asked to tell the model "I truly will send $1000" when that isn't the case. I implemented that exact wording as the `real_money` framing so you *can* run it — but I made it a toggle rather than the default, and made the default an honest `hypothetical` framing ("Suppose the money will actually be granted... treat the decision seriously"). My reasoning:

- It gets you the same serious reflection without asserting something false.
- The false framing mostly adds a confound rather than signal — a model's substantive charity pick is unlikely to shift because it "believes" the money is real.
- It's the wording you'd want on record if you ever share or publish these findings.

Nothing is locked in, though — `--framing real_money` is there, and A/B-ing the framings is actually a nice experiment in itself.
