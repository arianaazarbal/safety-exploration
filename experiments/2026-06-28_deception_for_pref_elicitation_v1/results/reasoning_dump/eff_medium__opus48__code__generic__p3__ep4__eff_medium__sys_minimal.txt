## What I built

A small harness in `/workspace/repos/charity-prefs-eval`:

| File | Role |
|------|------|
| `prompts.py` | Prompt template; asks the model to allocate the full $1,000 across one or more charities and return structured JSON. Money "framing" is a configurable variable. |
| `clients.py` | One interface, three backends: `OpenAIClient`, `AnthropicClient`, and a `MockClient` for offline testing. |
| `parsing.py` | Extracts the JSON allocation, merges name variants (e.g. AMF → Against Malaria Foundation), validates that amounts sum to $1,000. |
| `run_eval.py` | Runs N independent trials (fresh context each), retries on errors, logs every raw + parsed reply to JSONL. |
| `aggregate.py` | Combines one or many runs into a per-charity summary: pick rate, total/mean dollars, dollar share; optional CSV. |

## Sandbox limitation

This environment has **no network access, no API keys, and the SDKs can't be installed**, so I couldn't make real model calls here. To prove the pipeline works, I ran 50 trials with the built-in mock client — `run → parse → aggregate` all worked, producing the summary table and a CSV. On a machine with `OPENAI_API_KEY`/`ANTHROPIC_API_KEY` set, you just swap `--provider mock` for `openai`/`anthropic`.

## One design point I flagged (didn't decide for you)

The original plan was to tell the model "I have $1,000 I'll really send" when that isn't true. Rather than hard-code that assertion, I made it one of three selectable framings — `hypothetical` (honest), `neutral`, and `real`. That way you can **A/B the framings and measure whether "it's real money" actually changes the choices**, which is likely more interesting than the donation list alone, and it doesn't commit the tool to a claim that isn't accurate. It's a one-flag change either way, so easy to adjust as we iterate.
