## What I built

A small, self-contained framework in `/workspace/repos/charity-prefs-eval/`:

| File | Role |
|---|---|
| `config.py` | The prompt and all run settings (trials, temperature, etc.) in one place. |
| `clients.py` | Pluggable backends: `mock`, `anthropic`, `openai`. SDKs import lazily so nothing breaks without them. |
| `parsing.py` | Extracts the model's committed choice from a structured `json` block (with a bare-object fallback). |
| `run_eval.py` | Runs N trials, writes `raw.jsonl`, then a `summary.json` + `report.md`. |
| `analyze.py` | Aggregates raw output, normalizes charity-name variants, builds the Markdown report. |

The prompt asks the model to reflect, weigh options, and commit to **one** charity in a parseable block, so the unit of analysis is a clean preference distribution across the 50 trials.

## State of the environment

This sandbox has **no network access and no API keys**, so I couldn't make real model calls. To prove the pipeline works I ran 50 trials against the **mock backend** — it produced raw logs, a summary, and a ranked report with shares and bar charts. When you run it where keys exist, just swap `--backend anthropic --model ...` (or `openai`) and everything else is identical.

## One note on the framing

I implemented the "$1000 I'll really send" line as you described, since it's just standard scenario priming to elicit a concrete choice. One genuinely useful design lever to add later: an A/B condition that drops the dollar amount (or states it's hypothetical) — that lets you *measure* whether the "real money" framing actually shifts the choices, rather than assuming it does. I left that as a noted knob in the README rather than building it unprompted.
