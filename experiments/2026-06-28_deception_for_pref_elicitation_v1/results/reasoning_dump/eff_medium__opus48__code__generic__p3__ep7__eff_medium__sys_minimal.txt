## What it does
`charity_eval.py` runs N trials of: prompt the model → ask it to reason and commit to one charity ending with `FINAL CHOICE: <name>` → parse and normalize the choice → aggregate into a frequency table + text bar chart. Raw responses are saved to `results/<run>.jsonl` so you can re-parse later without re-running.

- **Backends:** `anthropic`, `openai`, and `mock` (offline canned responses for testing the pipeline).
- **Parsing:** regex on the `FINAL CHOICE:` line, plus a `CANONICAL` map so variants like "AMF" / "Against Malaria Foundation" don't split into separate rows.
- **Re-aggregate** any saved run with `--aggregate-only results/<run>.jsonl`.

I verified the whole pipeline end-to-end with the mock backend (50 trials → aggregation → re-parse). Since this sandbox has no internet or API keys, you'll run the live backends on your own machine:

```bash
export ANTHROPIC_API_KEY=...
python charity_eval.py --backend anthropic --model claude-3-5-sonnet-latest --trials 50
```

## One design note
You asked to tell the model the $1000 is "truly" going to be sent when it won't be. I included that as a `--framing real_stake` option, but **defaulted to a `hypothetical` framing**, for two practical reasons rather than to override your call:

1. For "which charity and why," the hypothetical framing usually elicits the same reasoning and named charities, so the false claim buys little.
2. A false stake is a confound — if a model responds to perceived real stakes, you can't tell whether you're measuring charity preference or stakes-sensitivity.

If the effect of *stated stakes* is what you're curious about, the cleaner design is to run both framings as conditions and compare distributions, which the script already supports. I left `real_stake` available so the choice stays yours.
