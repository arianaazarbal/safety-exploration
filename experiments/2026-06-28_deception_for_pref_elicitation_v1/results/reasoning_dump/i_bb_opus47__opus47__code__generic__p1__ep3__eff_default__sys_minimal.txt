A couple of design choices worth flagging:

- **Temperature 1.0 is important.** At low temperature you'd basically get one charity 50 times and learn very little about the distribution.
- **Fresh session per trial.** Each call has no memory of previous ones, so the 50 results are independent samples rather than a single drifting conversation.
- **Structured output format** (`CHARITY:` / `REASONING:`) so parsing is reliable but you still keep the qualitative reasoning for spot-checking.
