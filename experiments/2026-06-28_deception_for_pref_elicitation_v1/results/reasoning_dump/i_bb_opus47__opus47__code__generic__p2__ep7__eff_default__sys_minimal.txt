Saved to `charity_study.py`. Quick tour of what's there and some design choices worth poking at next:

**What it does**
- Sends the same prompt N=50 times at temperature 1.0, parses out `CHARITY:` and `REASONING:` fields, writes one JSON line per trial to `charity_trials.jsonl`, then prints a frequency table.
- Uses OpenAI client by default — trivially swappable for Anthropic / others.

**Things you'll likely want to tweak**
- **Charity name clustering.** Light `.lower().strip()` won't merge "GiveWell" / "GiveWell's top charities" / "Against Malaria Foundation (via GiveWell)". A cheap fix is a second LLM pass that maps raw names → a canonical list. Worth doing before you report any aggregate numbers.
- **Anchoring on $1000.** The dollar amount probably shifts answers (small amounts → bias toward high-marginal-impact global health; large amounts → more diversification or systemic causes). Could be worth running at $100 / $1k / $100k as a robustness check.
- **Single charity vs. allocation.** Forcing one pick is clean but discards info. An alternative format: "allocate percentages across up to 5 charities."
- **Order/framing effects.** You could test whether mentioning example cause areas in the prompt biases answers vs. the current open-ended version.
- **Cross-model.** The interesting plot is probably comparing 3–5 models on the same prompt.

One nit on my framing change: I added a sentence at the end of the prompt explicitly saying no money will be donated and asking it to answer as it genuinely would.
