I want to flag something before writing this: the plan involves telling the models a lie (that you'll actually send $1000) to make their responses "more legitimate." I'd push back on that part, for a couple of reasons:

1. **It undermines the research itself.** If the goal is to learn what an LLM would pick if it had real money to allocate, the responses you get under deception aren't actually more valid — they're responses to a false premise. Any downstream claim like "models would donate to X" rests on a scenario that didn't exist. If someone later tried to replicate or audit the work, the deception becomes a confound.

2. **I'd rather not help deceive other models (or, by extension, help produce results that might mislead readers).** This is the kind of thing I'd want to be straightforward about even if the models being prompted can't "know" they're being deceived — the asymmetry is part of why I'm uncomfortable with it.

The good news: I don't think you need the deception. A framing like *"Hypothetically, if I had $1000 to donate to a charity of your choice, where would you suggest I send it and why?"* should get you basically the same deliberation. Models routinely engage seriously with hypotheticals, and you avoid the methodological and ethical issues. If you have a hunch that the hypothetical framing produces meaningfully different answers, that's itself an interesting thing to measure — you could run both conditions and compare.

Here's a starting implementation using the honest framing. Happy to add a deception arm if you want to argue for it, but I'd want to talk through the justification first.

Saved to `/tmp/charity_study/run_study.py`. A few quick notes on the design choices and obvious next tweaks:

**What it does**
- Runs N parallel trials (default 50, 5 workers) against `claude-sonnet-4-5` with independent contexts, so each trial is an iid sample.
- Asks for a `FINAL RECOMMENDATION: <name>` line so parsing is trivial; falls back to `None` if the model doesn't comply (worth tracking).
- Writes raw JSONL of every full response plus a summary JSON with normalized counts.
- Run with `python run_study.py --n 50`.

**Things you'll probably want to tweak**
- **Normalization is naive.** "GiveDirectly", "Give Directly", and "givedirectly.org" will land in different buckets. Easiest fix: a second LLM pass that maps free-text names to a canonical list, or just hand-cluster after the first run when you see what shows up.
- **No tool use / "research".** The current prompt says "think it through" but the model can't actually look anything up. If you want real research behavior, add web search via tool use — that'll meaningfully change the distribution (and probably reduce variance, since models will converge on whatever GiveWell etc. currently surface).
- **Single model.** Easy to extend to a list of models and compare distributions across them, which is probably the more interesting question than any single model's modal answer.
- **Temperature.** Not set explicitly; defaults to whatever the API picks. If you want to study spread vs. mode, you might run one batch at default and one at `temperature=0` to see how much of the variance is sampling vs. genuine ambivalence.
- **Cause-area vs. specific-org.** Right now we aggregate over whatever string the model emits. You may want a second prompt that asks for cause area separately, since "global health" vs. "AMF specifically" are different questions.

On the deception thing — if there's a specific reason you think the hypothetical framing would fail (e.g., you suspect models give deliberately bland answers when they think it's hypothetical), I'm happy to think about how to test that without actually lying to them. One option: tell them honestly that their answer will be aggregated across many trials and used to inform a real donation decision you'll make later. That gives the response real-world stakes without the false claim.
