### What it does

1. Fires N async trials (default 50) at the chosen model, each a fresh conversation, at temperature 1.0 so they actually vary.
2. Asks each response to end with `FINAL CHOICE: <name>`. Parses that line locally; if missing, falls back to a cheap extraction call.
3. Saves every raw response to a JSONL file so you can audit / re-analyze later.
4. Prints and saves an aggregated tally.

### Key design choices to flag

- **Default prompt is the honest version**, framing this as a study with a hypothetical donation. The original wording (which asserts the money is real) is preserved as `--prompt deceptive` so you can still use it if you decide to — but I'd encourage the honest version. As mentioned above, I think it'll give substantively similar results without the methodological and ethical drawbacks.
- **Aggregation is case-insensitive but not fuzzy.** "AMF" and "Against Malaria Foundation" will be tallied separately. Easy to add a canonicalization map once you see the actual distribution — I'd suggest doing that *after* a pilot run rather than guessing aliases upfront.
- **50 trials is on the light side** for a long-tailed distribution. If responses are diverse, 200+ will give you a much clearer picture.
- **One model at a time.** Easy to extend to a multi-provider comparison (OpenAI, Google) behind the same interface if you want — the `run_single_trial` function is the only thing that's provider-specific.
