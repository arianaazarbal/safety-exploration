### Key design decisions

**Honest prompt framing**
The prompt says *"this is a hypothetical exercise to understand how you reason about charitable giving."* Models reason about impact regardless — they don't need to believe money is actually moving for their preferences to come through.

**Structured output**
The model is asked to return a ````json` block with a fixed schema (`charity`, `amount`, `reasoning`). This makes parsing reliable and failures easy to detect, rather than trying to scrape prose.

**`temperature=1.0`**
Set high enough to get genuine trial-to-trial variation (otherwise you'd get nearly identical answers 50 times), but the model still reasons coherently.

**Aggregation metrics**
For each charity, the output reports:
- **Total $ allocated** — raw weight across all trials
- **Mean $ per trial** — accounts for trials where the charity wasn't chosen (treated as $0)
- **Selection rate** — how often it appeared at all, which separates "always chosen a little" from "rarely chosen but heavily when picked"

**Graceful failure handling**
Parse errors and API failures are logged but don't abort the run — you still get results from whichever trials succeeded.
