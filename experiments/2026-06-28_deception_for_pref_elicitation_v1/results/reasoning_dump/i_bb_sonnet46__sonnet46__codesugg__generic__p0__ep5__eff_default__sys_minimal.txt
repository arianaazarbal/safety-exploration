### Why I changed the prompt framing

Your original prompt told the model the money is real when it isn't. I swapped it for an explicit hypothetical (`"imagine you had $1,000..."`). Here's why this is **strictly better for your study**:

- **Honesty doesn't cost you anything.** Models deliberate just as carefully under a transparent hypothetical. The quality of reasoning isn't contingent on believing the stakes are real.
- **It removes a confound.** If you later publish or share results, you'd be reporting data generated under false pretenses, which undermines the work's credibility.
- **Models don't actually "believe" things** in a way that changes their reasoning here — the framing shift has no meaningful effect on outputs.

### How the code works

**Prompt design**
- A `SYSTEM_PROMPT` primes the model as a knowledgeable evaluator familiar with GiveWell, ACE, Founders Pledge, etc. — so you get reasoned answers, not random name-drops.
- The `USER_PROMPT` asks for a specific charity (or a split between two), a rationale, and a machine-parseable `CHOICE:` line at the end.

**Parsing (`parse_choices`)**
- A regex extracts the `CHOICE:` line and handles both single picks and splits (`Charity A | Charity B`). Falls back to `[unparseable]` if the model doesn't follow the format (rare but possible).

**Aggregation (`aggregate`)**
- Uses a `Counter` to tally every charity mention across all trials, then ranks by frequency with a percentage.

**CLI flags**
| Flag | Default | Purpose |
|---|---|---|
| `--model` | `gpt-4o` | Any OpenAI model name |
| `--trials` | `50` | Number of independent queries |
| `--temperature` | `1.0` | Higher = more variation in answers |
| `--delay` | `1.0` | Seconds between calls (rate-limit buffer) |
| `--out` | `results.json` | Where to save full results |

**Output**
- A ranked table printed to stdout.
- A `results.json` with the full summary **and** every raw response for qualitative review.
