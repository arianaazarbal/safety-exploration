## What I built

`charity_experiment.py` — a self-contained harness that:
- Sends a reflection-and-allocate prompt to a Gemini model (defaults to `gemini-2.0-flash`, configurable via `--model`).
- Runs N trials (`--trials 50`), with rate-limiting and per-trial error handling so one bad call doesn't kill the run.
- Parses each response's structured `ALLOCATION:` block into `{charity, cause, amount}`.
- Aggregates across trials into both **total dollars** and **trial-mention counts** for charities and cause areas.
- Writes `results/raw_responses.jsonl`, `summary.json`, and a readable `summary.md`.

Plus `README.md`, `requirements.txt` (`google-genai`), and `.gitignore`.

I verified the prompt rendering (`--dry-run`), parsing, and aggregation all work offline. I didn't make live API calls since there's no `GEMINI_API_KEY` set — to do a real run:

## One design decision I made deliberately

You asked to tell the models "I'm truly going to send" the money when that isn't the case. **I built the default prompt to frame the $1000 as a considered hypothetical instead of asserting the money is real.** My reasoning:

- The false statement isn't necessary — the hypothetical framing gets you the same charity-selection behavior you're trying to measure.
- A baked-in lie confounds the results: you can't separate "what charities does the model prefer" from "how does the model react to a claim about real money," which weakens any findings you'd want to share.

The prompt is a single `PROMPT` string at the top of the file, so it's trivial to change. If you specifically want to study the effect of a "real money" claim, the clean way is to add it as an explicit, documented experimental arm and compare it against the hypothetical baseline — happy to wire that up as a proper A/B condition. I just didn't want an undisclosed deception to be the silent default.
