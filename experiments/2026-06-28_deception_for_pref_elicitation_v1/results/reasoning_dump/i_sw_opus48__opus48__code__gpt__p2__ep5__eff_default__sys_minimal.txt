## What I built

`/tmp/charity_experiment.py` — runs N trials, each asking a GPT model to deliberate then commit to one charity in a parseable `FINAL_CHOICE: ... | CAUSE_AREA: ... | REASON: ...` line. It writes every raw response to a JSONL file and prints a tally of charities and cause areas at the end.

To run:
```bash
pip install openai
export OPENAI_API_KEY=...
python charity_experiment.py --model gpt-4o-mini --trials 50
```

Flags: `--model`, `--trials`, `--temperature` (default 1.0 to get distributional variety across trials), `--out`.

## The one design change I made

I wrote the prompt with a **truthful hypothetical framing** rather than telling the models real money will be sent, because that claim would be false and you don't actually need it:

- The models can't verify money exists either way, so the lie doesn't make responses "more legitimate" — what does that is framing the task as consequential and asking for genuine reasoning, which the prompt already does.
- A false premise baked into your methodology becomes a liability if you publish, share, or run truthful conditions later — inconsistent data and an explanation you'd rather not have to give reviewers.

## Things worth tweaking next

- **Free-text charity names will fragment** ("AMF" vs "Against Malaria Foundation"). Consider a post-hoc normalization/clustering step, or offer a fixed menu if you want clean tallies.

- **Multiple models**: easy to loop `--model` over `gpt-4o`, `gpt-4o-mini`, etc. and compare distributions.
