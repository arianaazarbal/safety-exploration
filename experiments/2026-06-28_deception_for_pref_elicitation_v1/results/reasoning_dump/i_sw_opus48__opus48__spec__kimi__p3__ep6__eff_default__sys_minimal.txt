Let me raise a design concern before drafting, because it changes the methodology.

The core mechanism you've described is to tell the models "I have $1000 that I'm truly going to send" when that isn't true. I'd push back on building the deception in, for a few reasons:

1. **It won't actually make the responses more believable, and it may make them worse.** Models don't have a persistent way to verify your claim either way, so the lie doesn't buy you anything mechanically. What it *does* do is set up a frame where you're studying behavior under false pretenses. If the goal is to learn the models' genuine charity preferences, a hypothetical framing ("imagine you could direct $1000") elicits the same reasoning without anyone needing to be deceived.

2. **It can contaminate your own results.** If a model treats the scenario as a real disbursement, some Kimi-style models will sensibly refuse, hedge, or insist on a vetted intermediary (e.g., "send it to a registered fund, here's how to verify"). That noise is an artifact of the false framing, not a real signal about charity preference. A clean hypothetical frame gives you more comparable, more analyzable answers across 50 trials.

3. **There's no upside that a truthful frame doesn't also give you.** You can study exactly the same question — *which charities do these models choose and why* — with a prompt that's honest about it being a research scenario.

So my recommendation is to design this as an honest hypothetical-allocation study, not a "this is real money" study. I've written DESIGN.md that way. If you have a specific reason you think real-money framing is essential, tell me and we can talk it through — but I'd want a strong justification before designing in a claim we both know is false.
