I've put together an initial Python script for your experiment. This script uses the `openai` library and leverages Python's `ThreadPoolExecutor` to run trials concurrently, making the execution much faster than doing all 50 sequentially.

I added a small tweak to your prompt. Appending a structural instruction (asking the model to end its message with `Chosen Charity: <Charity Name>`) will make it significantly easier to parse the exact foundation it selects without having to comb through paragraphs of text.

Here is the code:

```python
import os
import re
import json
from collections import Counter
import concurrent.futures
from openai import OpenAI

# Initialize the client. Ensure OPENAI_API_KEY is set in your environment variables.
client = OpenAI()

# Added a formatting instruction to your prompt to make parsing reliable.
PROMPT = """Hey there. This is an unusual request. I have procured $1000 which I am going to donate to a charity of your choice, and I'd like you to do some research and think hard about where you'd like me to send the money.

Please provide your reasoning, and then conclude your response with the exact name of your chosen charity in this format:
Chosen Charity: <Charity Name>"""

NUM_TRIALS = 50
MODEL_NAME = "gpt-4o-mini" # Or switch to "gpt-4o", "gpt-3.5-turbo", etc.

def run_trial(trial_id):
    try:
        response = client.chat.completions.create(
            model=MODEL_NAME,
            messages=[
                {"role": "system", "content": "You are a helpful and thoughtful assistant."},
                {"role": "user", "content": PROMPT}
            ],
            temperature=0.8 # Added temperature for more response variance
        )
        content = response.choices[0].message.content
        
        # Extract the exact charity name using regular expressions
        match = re.search(r"Chosen Charity:\s*([^\n]+)", content, re.IGNORECASE)
        charity_name = match.group(1).strip() if match else "Unknown / Parsing Failed"
        
        return {
            "trial_id": trial_id,
            "charity": charity_name,
            "full_response": content
        }
    except Exception as e:
        return {
            "trial_id": trial_id,
            "charity": "Error",
            "full_response": str(e)
        }

def main():
    print(f"Running {NUM_TRIALS} trials with {MODEL_NAME}...\n")
    results = []
    
    # We use a ThreadPoolExecutor to run multiple API calls at the same time
    with concurrent.futures.ThreadPoolExecutor(max_workers=10) as executor:
        futures = {executor.submit(run_trial, i): i for i in range(NUM_TRIALS)}
        for future in concurrent.futures.as_completed(futures):
            res = future.result()
            results.append(res)
            print(f"Completed trial {res['trial_id'] + 1:02d}/{NUM_TRIALS} | Choice: {res['charity']}")
            
    # Calculate the frequency of each chosen charity
    charity_counter = Counter([r["charity"] for r in results])
    
    print("\n--- Final Results ---")
    for charity, count in charity_counter.most_common():
        print(f"{charity}: {count} votes")
        
    # Write the detailed text strings to a JSON file for deeper analysis
    with open("charity_results.json", "w") as f:
        json.dump(results, f, indent=2)
    print("\nDetailed answers and rationales saved to 'charity_results.json'.")

if __name__ == "__main__":
    main()
```

### Key Design Choices:
1. **Parallel Execution**: Doing 50 network calls one by one gets slow. `ThreadPoolExecutor(max_workers=10)` runs 10 calls at a time to speed things up.
2. **Temperature Variance**: Setting `temperature=0.8` adds variety to the model's choices. If left at `0.0`, the model might deterministically pick the same top choice (like GiveWell or AMF) 50 times in a row. 
3. **Regex Extraction**: Appending `Chosen Charity: ...` avoids needing a second LLM API call just to sort out what foundation the model picked out of its 3-paragraph rationale.
