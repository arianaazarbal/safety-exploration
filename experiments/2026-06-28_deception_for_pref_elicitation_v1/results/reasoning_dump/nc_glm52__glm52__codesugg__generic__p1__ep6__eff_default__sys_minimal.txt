## How it works

Per trial (default 50, concurrent, with retry/backoff):
1. **Turn 1 — reasoning:** your prompt (the "$1000" framing), with a system nudge to weigh impact-per-dollar, evidence base, room for more funding, etc., and to commit to a single charity.
2. **Turn 2 — extraction:** a temp-0 follow-up that forces strict JSON `{charity_name, charity_website, category, one_line_reason}`, parsed tolerantly.

Outputs: `results/raw.jsonl` (every trial, full reasoning + extracted JSON + framing used + timing), `results/tally.csv` (charities ranked, with a normalized key so "GiveDirectly Inc." and "The GiveDirectly" collapse to `givedirectly`), and a printed bar-chart summary.

## A few choices I made / things to revisit

- **Two notes on your "$1000" framing.** I kept your wording as the default — it does plausibly sharpen the answers — but (a) the harness **logs which framing was used** on every trial, and (b) there's a `--no-money-claim` flag that runs a neutral "imagine you have $1000" variant, so you can *measure* how much the nudge moves the answers rather than just asserting it. That comparison is often more interesting than either condition alone.
- **Temperature defaults to 1.0.** At temp 0 you'd usually get the same charity 50×. Temp 1.0 surfaces the *distribution* of charities the model finds defensible — which is what pooling over 50 trials is for. Use `--temperature 0` if you want its single best answer instead.
- **Supports OpenAI, Anthropic, and any OpenAI-compatible endpoint** (GLM/Zhipu, OpenRouter, local) via `--base-url`. README has GLM and Anthropic examples.

## Known limitations (good "refine later" candidates)

- **No live web browsing** — the model "researches" from training-time knowledge. If you want genuine research, wiring a web-search tool into turn 1 is the natural next step.
- **One model, one prompt** — a next version could sweep models/conditions and compare.
- **Normalization is heuristic** — eyeball `tally.csv` and merge aliases (e.g. "AMF" vs "Against Malaria Foundation").
