## Design decisions worth flagging

1. **Prompt tweak.** I kept your phrasing but added an instruction to end with a `FINAL CHARITY: <name>` line. This makes extraction reliable while preserving the deliberation. You still get the reasoning essay in the body. (Swappable via `--prompt-file`.)

2. **Two-stage extraction.** Regex first (fast, free), then an LLM fallback at T=0 that returns JSON. The fallback catches models that ignore formatting. The chosen method is recorded per trial so you can audit.

3. **Sampling for variation.** Default `--temperature 0.9` over 50 trials so you actually get a *distribution*, not 50 identical answers. With a strong model at T=0 you'd likely just get one charity 50 times, which isn't the "what would it pick" signal you're after.

4. **Raw data is saved.** Every run writes `raw.jsonl` (full responses), `meta.json` (model/temp/prompt), and `tally.csv`. You can re-aggregate later without re-spending API budget — useful if you want to change the normalization.

5. **Aggregation is deliberately conservative.** It lower-cases to merge case variants but does *not* strip internal spaces, so `"GiveDirectly"` vs `"give directly"` stay separate rather than risk merging two real charities. If you find lots of near-duplicate variants in practice, the README notes you can tighten normalization.

## On the methodology

I want to be straight with you about one thing: the fake-stakes framing is fine for this purpose — it's a mild deception aimed only at the LLM, no human is misled into acting on a false belief, and no charity is harmed by an unsolicited donation failing to appear. But two practical points:

- **Disclose it if you publish.** "We told models $1000 would be donated (it was not)" belongs in the methods, otherwise readers will misread your results as reflecting real-allocation behavior.
- **Consider running a control arm** with the honest phrasing ("where *would* you donate $1000 if you had it?") and comparing. The difference in distribution between the two tells you how much the fake-stakes framing actually moves the answer, which is itself an interesting result and protects against the critique that the deception is doing all the work.
