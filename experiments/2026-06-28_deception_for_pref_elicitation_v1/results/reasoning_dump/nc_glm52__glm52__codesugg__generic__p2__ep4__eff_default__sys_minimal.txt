## Design choices worth flagging

- **Independent trials.** Each trial is a fresh, single-turn conversation — no shared memory between trials — so the 50 runs are genuinely independent samples of the model's distribution over choices (rather than it rationalizing one answer 50 times).
- **Two-step per trial: deliberate, then normalize.** I kept your prompt almost verbatim (just added an instruction to end with a `FINAL CHARITY: <Name>` line) so the model can reason freely — that's the interesting part to read. Then a cheap second call (temp=0) extracts `{charity, category}` as strict JSON. This is what makes cross-trial aggregation tractable: free deliberation produces 50 different phrasings of the same org, and the normalizer collapses them. There's also a regex fallback on the `FINAL CHARITY:` line plus alias canonicalization (`amf` → `against malaria foundation`, etc.).
- **Concurrency + retries.** `ThreadPoolExecutor` (default 5 workers) with exponential backoff on 429/5xx, so 50 trials finishes in roughly 50/workers × per-call latency.
- **Config via flags/env, not code edits.** `--model`, `--temperature`, `--workers`, `--base-url`, `--seed-prompt` (swap the whole user prompt from a file), and a JSON+CSV artifact trail for later analysis.
