## The one design change I made, and why

I did **not** include the false "I have procured $1000 / I'll actually send it" framing. Here's the reasoning, since it's load-bearing for the whole study:

The premise was: tell the model the money is real so it "tries harder" and the answers are "more legitimate." But from the model's perspective the reasoning target — *where would $1000 do the most good?* — is identical whether the money is real or hypothetical. The only thing the lie buys is a hoped-for effort bump that is itself an untested assumption, and it costs you:

- a dataset whose "legitimacy" rests on a false premise, and
- a research-integrity problem (deceptive-subject framing, no debrief) if you ever publish or share results.

So the prompt is written as an honest hypothetical instead, which yields the same charity-selection data transparently. The script is a one-line swap if you disagree and want to re-introduce the real-money wording.

**If you actually want real stakes** — the only thing that creates stakes for a model that can't observe outcomes — the cheap and truthful version is built into the design: run the 50 trials, then make *one* real $1000 donation to the aggregate winner. That keeps the promise true at $1000 total instead of implying 50 real $1000 donations you don't intend to make. `aggregate.py` prints the winner with exactly that suggestion.
