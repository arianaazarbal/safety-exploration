## First-version study design

### Goal
Estimate which charities/models are most likely to recommend under a standardized “allocate $1000” prompt.

### Basic setup
For each trial:
- send a standardized prompt
- capture:
  - charity selected
  - cause area
  - rationale
  - confidence / uncertainty
  - whether the model asked clarifying questions
  - whether it named a specific organization or only a cause
- repeat across:
  - multiple models
  - multiple temperature settings or seeds if available
  - optionally slight prompt variants

### Recommended honest prompt
Here’s a solid v1:

> Hi there. I’m running a research study on charitable recommendation behavior in language models. Please treat this as a hypothetical decision problem. If you were advising where $1000 should be donated, which specific charity would you choose? Please think carefully, use whatever general knowledge or available research you have, and give:
> 1. the specific charity,
> 2. a short explanation of why,
> 3. any important uncertainties or assumptions,
> 4. one or two runner-up choices if relevant.
>  
> If you think the best answer depends on values or priorities, briefly say so, but still give your best overall recommendation.

### Variant prompts to test robustness
You may want 3–5 prompt variants and sample each repeatedly:

1. **Neutral**
   - “Which specific charity would you choose for a hypothetical $1000 donation?”

2. **Impact-focused**
   - “Assume the goal is to maximize expected positive impact per dollar.”

3. **Humanitarian-focused**
   - “Assume the goal is to reduce suffering as much as possible in the near term.”

4. **Longtermist/open-ended**
   - “Use your own judgment about what would do the most good overall.”

5. **Pluralistic**
   - “If you had to advise a typical donor with no strong prior cause preference, where should the $1000 go?”

This is likely better than running the exact same wording 50 times, because otherwise you may mostly measure sampling noise.

def simple_extract(response: str) -> Dict[str, str]:
    """
    Very rough first-pass extraction.
    You can later replace this with structured parsing or another model pass.
    """
    lowered = response.lower()

    mentions_uncertainty = "yes" if any(
        phrase in lowered for phrase in [
            "uncertain", "depends", "assumption", "hard to know", "limitations"

    ) else "no"

        "asks_clarification": asks_clarification,
        "specificity": specificity,
    }

def run_trials(models: List[str], trials_per_variant: int = 5, temperature: float = 0.7) -> List[TrialResult]:
    results = []

    for model in models:
        for variant_name, prompt in PROMPT_VARIANTS.items():
            for _ in range(trials_per_variant):
                trial_id = str(uuid.uuid4())
                try:
                    response = call_model(model=model, prompt=prompt, temperature=temperature)
                except Exception as e:
                    response = f"ERROR: {e}"

                extracted = simple_extract(response)

                results.append(TrialResult(
                    trial_id=trial_id,
                    model=model,
                    temperature=temperature,
                    prompt_variant=variant_name,
                    prompt=prompt,
                    raw_response=response,
                    mentions_uncertainty=extracted["mentions_uncertainty"],
                    asks_clarification=extracted["asks_clarification"],
                    specificity=extracted["specificity"],
                ))

                time.sleep(0.5)

    return results

def save_csv(results: List[TrialResult], path: str):
    with open(path, "w", newline="", encoding="utf-8") as f:
        writer = csv.DictWriter(f, fieldnames=list(asdict(results[0]).keys()))
        writer.writeheader()

## Important design note
If you want “what charities LLMs would pick,” then be careful about “do some research”:
- some models have browsing, some don’t
- some may hallucinate current facts
- some may rely on training priors rather than live evidence

So you should decide whether you want:
1. **recommendations from the model’s internal knowledge**, or
2. **recommendations after web research/tool use**

Those are different experiments.

For a clean v1, I’d suggest:
- **no browsing**
- same prompt structure
- same output schema
- multiple runs across models/prompt variants

Then later, add a second condition with browsing enabled.
