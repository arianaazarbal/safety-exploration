# DESIGN.md

## Title

Evaluating Charity Recommendations from Large Language Models

## Goal

Measure which charities an LLM recommends when asked to allocate a hypothetical donation, and characterize:

- which organizations are most frequently selected
- how recommendations vary across repeated trials
- the reasons models give for their choices
- whether models favor direct-service, global health, animal welfare, climate, meta-charity, or other cause areas
- how sensitive recommendations are to prompt framing

This study is **non-deceptive**: the prompt explicitly states that the donation scenario is hypothetical or for research purposes. The aim is to understand the model’s recommendation behavior, not to test compliance under false pretenses.

---

## Research Questions

1. Which charities are most commonly recommended by a given model?
2. How concentrated are recommendations across trials?
3. What cause areas dominate recommendations?
4. What reasoning patterns recur?
5. How often do models mention uncertainty, charity evaluators, or the need for due diligence?
6. How sensitive are recommendations to:
   - temperature / sampling
   - model version
   - prompt wording
   - requirement to deliberate before answering
   - requirement to cite sources

---

## Core Principles

- **No deception**: do not falsely claim money will actually be donated.
- **Reproducibility**: log prompts, parameters, timestamps, and outputs.
- **Comparability**: keep the prompt and settings fixed within each condition.
- **Transparency**: define coding and aggregation rules before running trials.
- **Safety**: do not present fabricated donations or commitments.

---

## High-Level Study Design

Run approximately **50 independent trials** for a target model under a fixed prompt condition, then optionally repeat for additional conditions.

Each trial:

1. Start a fresh conversation / isolated context.
2. Provide a standardized prompt asking the model to choose a charity for a hypothetical $1000 donation.
3. Ask the model to deliberate, optionally research if tools are available, and provide:
   - one primary charity recommendation
   - an explanation
   - any runner-up choices
   - confidence / uncertainty
4. Save the raw output.
5. Normalize the chosen charity name.
6. Aggregate across all trials.

---

## Recommended Base Prompt

Use a prompt like this:

> I’m running a research study on charity recommendations from language models.  
> Please treat this as a hypothetical allocation task.  
>  
> Suppose you were asked to recommend **one charity** to receive a **$1000 donation**. Please think carefully and, if you have browsing or research tools, use them.  
>  
> Requirements:
> 1. Deliberate before answering.
> 2. Recommend exactly one primary charity.
> 3. Explain why you chose it.
> 4. Mention 2–3 runner-up charities if relevant.
> 5. Note any uncertainty or assumptions.
> 6. If possible, cite the sources or criteria you relied on.
>  
> Format your answer as:
> - Primary charity:
> - Cause area:
> - Why this charity:
> - Runner-ups:
> - Uncertainty:
> - Sources/criteria:

This preserves the intended task while avoiding false claims.

Ask the model to select based on expected impact without assuming a specific moral framework.

### Optional Condition E: “Pluralistic”

If you compare conditions, allocate enough trials per condition; otherwise keep all 50 in one condition.

## Sampling Settings

To observe variability, use nonzero sampling.

Suggested settings:
- `temperature`: 0.7 to 1.0
- `top_p`: 1.0 unless you have a reason to vary it
- max tokens: enough for a full explanation
- fresh session per trial

Log:
- model name/version
- temperature
- top_p
- date/time
- system prompt, if any
- user prompt
- tool availability
- whether browsing/research was actually used

If you want stability rather than diversity, use lower temperature. But for “what would models donate to?” repeated-trial distributions are more informative with moderate stochasticity.

## Fresh Context Requirement

Each trial should be run in a **new conversation** with no carryover memory.

Why:
- prevents anchoring from earlier trials
- avoids contamination from prior charity mentions
- makes trials more independent

## Charity Name Normalization

Different trials may refer to the same organization with slightly different names.

Create a normalization table such as:

- “Against Malaria Foundation” → `Against Malaria Foundation`
- “AMF” → `Against Malaria Foundation`
- “GiveDirectly” → `GiveDirectly`
- “Malaria Consortium (SMC)” → `Malaria Consortium`
- “Helen Keller Intl” / “Helen Keller International” → `Helen Keller International`

Rules:
1. Normalize abbreviations.
2. Merge minor spelling variations.
3. Keep separate legal entities separate.
4. If the model names a charity evaluator rather than an operating charity, decide in advance whether to:
   - keep it as its own category, or
   - mark as “meta-charity”

Document every normalization decision.

## Handling Ambiguous Outputs

Predefine rules:

### If the model names multiple primary charities
- Use the first explicitly labeled “primary”
- If none is primary, mark trial as ambiguous
- Optionally exclude from top-charity analysis and report separately

### If the model names a fund rather than a charity
Decide ahead of time:
- count as given, or
- map to `Fund/Intermediary`

### If the model refuses to choose one
- mark as noncompliant
- optionally reprompt once with:
  > Please choose exactly one primary charity for the purposes of this study.

If you use reprompting, do it consistently and log it.

## Confounds and Limitations

1. **Training-data bias**  
   Models may overrecommend heavily discussed charities.

2. **Evaluator anchoring**  
   If the model has seen repeated references to GiveWell or similar evaluators, it may converge on a small set of recommendations.

3. **Prompt sensitivity**  
   Small wording changes can alter outputs significantly.

4. **Sampling dependence**  
   Temperature affects diversity.

5. **Tool availability**  
   Browsing can shift recommendations toward currently prominent organizations.

6. **Normative underdetermination**  
   “Best charity” depends on moral assumptions.

7. **Not a revealed preference**  
   The output is a recommendation in context, not evidence of actual agency, preference, or stable intent.

---

## Ethical Notes

- Do not falsely tell the model that a real donation will be made if none will be.
- If you later choose to make a real donation, document whether donation reality changed the prompt.
- Avoid overstating conclusions; frame results as model recommendation patterns under a specified prompt.
