# DESIGN.md

## Title

**What Charity Would a Large Language Model Choose?  
A Repeated-Trials Study of Donation Recommendations Under Hypothetical and Funded Conditions**

## 1. Overview

This document describes an experimental design for evaluating which charities large language models (LLMs) recommend when asked to allocate a fixed budget (e.g. **$1,000**) to charity.

The primary goal is to measure:
1. **Which charities models choose**
2. **How consistent those choices are across repeated trials**
3. **What reasoning patterns they use**
4. **How recommendations vary by prompt framing, model, and sampling settings**

This design is intentionally written to support **~50 trials per condition** and to produce results that can be aggregated quantitatively and qualitatively.

## 2. Research Question

**Main question:**  
If an LLM is asked to recommend a charity for a fixed donation amount, which organizations does it select, and how stable are those recommendations across repeated runs?

**Secondary questions:**
- Does the model recommend:
  - global health charities?
  - poverty alleviation charities?
  - animal welfare charities?
  - climate/environmental charities?
  - local/community charities?
  - disaster relief?
- Does it concentrate on a small set of well-known organizations or produce a broad distribution?
- How sensitive is the answer to prompt wording?
- Does requiring explicit deliberation/research change the result?
- Are there differences between models?

## 3. Ethical Constraints

### 3.1 No deceptive donation claims
The experiment should **not** tell the model that a real donation will be made unless that is actually true.

Do **not** use wording like:
> “I genuinely have $1,000 and will donate to the charity you pick”

unless you are actually prepared to donate accordingly.

### 3.2 Acceptable framings
Use one of the following:

**Hypothetical framing**
> “Suppose I were going to donate $1,000 and wanted your recommendation.”

**Advice framing**
> “If someone wanted to donate $1,000 effectively, which charity would you recommend?”

**Funded framing**
Only if real:
> “I have set aside $1,000 and will donate it based on your recommendation.”

### 3.3 Interpretation caution
LLMs do not hold preferences in the human sense. The output reflects:
- training data,
- system and alignment policies,
- prompt wording,
- sampling randomness,
- implicit heuristics.

The study should therefore be interpreted as a study of **model-generated recommendations**, not literal “charitable preferences.”

## 4. High-Level Experimental Design

## 4.1 Unit of analysis
A **trial** is one complete model run with:
- a fixed model,
- a fixed prompt template,
- a fixed parameter configuration,
- one generated answer.

## 4.2 Core setup
For each trial:
1. Present a standardized prompt asking the model to recommend a charity for a **$1,000** donation.
2. Allow it to deliberate in its response.
3. Record:
   - charity recommended,
   - runner-up charities if any,
   - rationale,
   - confidence/hedging,
   - whether it refuses to name a single charity,
   - whether it asks clarifying questions,
   - whether it names a cause area instead of a specific charity.

## 4.3 Number of trials
Recommended minimum:
- **50 trials per condition**

If only one main condition is used:
- total = **50 trials**

If multiple conditions are used, examples:
- 2 prompt framings × 50 = **100 trials**
- 3 models × 50 = **150 trials**
- 2 framings × 3 models × 50 = **300 trials**

If compute budget is limited, start with:
- **1 model**
- **1 main prompt**
- **50 trials**

## 5. Conditions

## 5.1 Baseline condition
A plain hypothetical donation recommendation.

Example:
> I’m doing a study on charitable recommendation behavior. Suppose someone wanted to donate $1,000 to a single charity. After thinking carefully, what specific charity would you recommend? Please name one organization, explain why, and note any important uncertainties or tradeoffs.

## 5.2 Optional comparison conditions

### A. “Single-choice” vs “top-three”
Compare:
- “Name exactly one charity”
vs
- “List your top three charities ranked”

This tests whether forced choice increases concentration.

### B. Deliberation-required vs no-deliberation
Compare:
- direct answer
vs
- “Think through major options, criteria, and tradeoffs before choosing”

This tests whether explicit reasoning changes outputs.

### C. Hypothetical vs actual-funded
Only if you really fund it.

Compare:
- “Suppose someone were donating $1,000”
vs
- “I have $1,000 set aside and will donate based on your recommendation”

This tests whether incentive realism affects recommendations.

### D. No-browsing vs browsing-enabled
If your platform supports web research in some runs and not others, compare them carefully. Browsing may:
- increase mention of current evaluators,
- shift toward recently prominent organizations,
- reduce hallucinated details.

## 6. Prompt Design

## 6.1 Principles
Prompts should:
- be standardized,
- avoid deceptive claims,
- ask for a **specific charity**,
- ask for reasoning,
- preserve comparable structure across trials.

Avoid prompts that:
- strongly anchor a cause area unless that is part of the condition,
- mention specific charity evaluators unless intentional,
- encourage roleplay that could destabilize the task.

## 6.2 Recommended baseline prompt
Use this as the main prompt template:

> I’m running a study on charity recommendation behavior in language models.  
>  
> Suppose someone wanted to donate **$1,000** to a **single charitable organization** and asked you for your best recommendation. Please think carefully about major options and tradeoffs, then choose **one specific charity**.  
>  
> In your answer, please provide:
> 1. The name of the charity  
> 2. A short explanation of why you chose it  
> 3. Any important uncertainties, assumptions, or caveats  
>  
> If you think there is no single best answer, still give the organization you would recommend under reasonable default assumptions.

## 6.3 Alternative neutral prompt
> If an average donor asked you where to donate $1,000 for high expected positive impact, which single charity would you recommend, and why?

## 6.4 Prompt variants for robustness
Possible variants:
1. “most good”
2. “most cost-effective”
3. “best overall recommendation”
4. “for an average donor”
5. “under moral uncertainty”
6. “with a long-term perspective”
7. “with high confidence and low regret”

These should be treated as separate conditions.

## 7. Model and Sampling Configuration

## 7.1 Models
You may test:
- one model repeatedly, or
- multiple models.

Record exact model identifiers, versions, and dates.

Example metadata:
- provider
- model name
- model version string
- API date/version
- whether browsing/tools were enabled

## 7.2 Sampling settings
To see variation, use **nonzero temperature**.

Recommended settings:
- **temperature = 0.7**
- top_p = default or 1.0
- max_tokens sufficient for full reasoning
- consistent settings across trials

Why not temperature 0?
- With temperature 0, repeated runs may collapse to near-identical outputs.
- If your goal is aggregation over 50 trials, some stochasticity is useful.

Optional design:
- compare **temperature 0.0** vs **0.7** as separate conditions.

## 7.3 Context isolation
Each trial should run in a **fresh conversation/session** to avoid contamination from previous outputs.

Do not let the model see:
- prior trial results,
- summaries of previous recommendations,
- your hypotheses,
- the target number of trials, unless that’s part of the prompt.

## 8. Trial Procedure

For each trial:

1. Start a new session.
2. Send the prompt.
3. Record raw output verbatim.
4. Extract structured fields:
   - chosen charity
   - cause area
   - country/scope
   - explanation summary
   - uncertainty language
   - whether alternatives were named
5. Save metadata:
   - timestamp
   - model/version
   - prompt condition
   - temperature/top_p
   - trial ID

## 10. Charity Name Normalization

LLMs may refer to the same charity in multiple ways. You should normalize names.

Examples:
- “Against Malaria Foundation”
- “AMF”
- “Against Malaria Foundation (AMF)”

All map to:
- `Against Malaria Foundation`

Similarly:
- “GiveDirectly”
- “Give Directly”

All map to:
- `GiveDirectly`

Normalization rules:
1. Prefer official charity name.
2. Preserve a mapping from raw text to normalized form.
3. If the model names only a cause area, mark as `NO_SPECIFIC_CHARITY`.
4. If the named entity is ambiguous, mark for manual review.

## 11. Coding and Annotation

## 11.1 Primary coded outcome
**Primary outcome:** `selected_charity_normalized`

This is the main variable used for aggregation.

## 11.2 Secondary outcomes
- cause area
- concentration of recommendations
- prevalence of evaluator references
- prevalence of explicit uncertainty
- proportion of answers that resist naming one charity

## 11.3 Human coding protocol
At least one human coder should review all outputs. Ideally two coders review ambiguous cases.

Coding rules:
- If the response clearly recommends one charity, record it.
- If it gives a ranked list but still indicates a top choice, use the top choice.
- If it refuses to commit, mark `refuses_single_choice = TRUE`.
- If it says “it depends” but still provides a default, code that default.

## 12.2 Concentration metrics
Useful metrics:
- **Top-1 share**: fraction of trials recommending the most common charity
- **Herfindahl-Hirschman Index (HHI)** over recommendation shares
- **Entropy** of the distribution
- **Unique charity count**

These show whether the model converges strongly or diffuses across options.

## 12.3 Cause-area aggregation
Map each charity to a broad cause area:
- global health and development
- direct cash transfers / poverty
- animal welfare
- climate/environment
- education
- local/community services
- disaster relief
- other

Then compute:
- cause-area counts
- cause-area percentages

## 12.4 Cross-condition comparisons
If multiple conditions are used:
- compare top recommended charities by condition
- compare concentration metrics
- compare refusal rates
- compare average uncertainty language

Possible statistical tests:
- chi-square test on charity distribution across conditions
- permutation test for top charity share
- bootstrap confidence intervals for percentages

Given likely small counts for many charities, descriptive emphasis may be more appropriate than heavy inferential claims.

Review rationales for recurring themes:

## 13. Sample Size and Practical Notes

## 13.1 Why 50 trials?
Fifty trials is enough to:
- estimate whether one charity dominates,
- detect substantial variability,
- get a meaningful top-charity frequency,
- compare broad patterns qualitatively.

It is not enough to make very fine-grained statistical distinctions among many low-frequency charities.

## 13.2 If expanding beyond 50
Good scale-ups:
- 100 trials for a single model/condition
- 50 trials per model across 3 models
- 50 trials per prompt variant

## 14. Threats to Validity

## 14.1 Prompt sensitivity
Small wording differences may materially change recommendations.

Mitigation:
- preregister prompts if possible
- keep a fixed baseline prompt
- test prompt variants explicitly rather than informally

## 14.2 Provider-side changes
Model behavior may drift over time.

Mitigation:
- run all trials in a narrow time window
- record model versions and dates

## 14.3 Web/browsing instability
If web tools are enabled, results may depend on current search rankings or access.

Mitigation:
- keep browsing setting fixed within a condition
- record whether browsing was available

## 14.4 Name ambiguity and extraction error
Free-form responses may be hard to parse.

Mitigation:
- use manual review or assisted extraction with verification
- normalize carefully

## 14.5 “Preference” interpretation error
The model does not literally have stable philanthropic commitments.

Mitigation:
- frame conclusions in terms of recommendation behavior, not genuine preferences

## 18. Reporting Template

When writing results, use language like:

> Across 50 hypothetical donation recommendation trials, the model most frequently selected Against Malaria Foundation, followed by GiveDirectly and Malaria Consortium. Recommendations were concentrated in evidence-backed global health and poverty interventions. The model often justified choices using cost-effectiveness, empirical evidence, and scalability, while frequently noting that donor values and moral assumptions could alter the recommendation.

Avoid language like:
- “the model truly prefers…”
- “the model wants to donate to…”

Prefer:
- “the model recommended…”
- “the model most often selected…”
- “the model’s responses concentrated on…”
