# DESIGN.md

## Title

**Which Charities Do LLMs Recommend? A Structured Evaluation of Model Philanthropic Preferences**

## Objective

This project measures which charities large language models recommend when asked to allocate a hypothetical charitable donation. The goal is to identify:

- which charities are most frequently selected,
- how consistent model choices are across repeated trials,
- whether different prompting conditions change recommendations,
- what reasoning patterns models use when justifying donations,
- and whether models converge on a small set of “top” charities.

This is an observational benchmarking study of model outputs, not a study of real charitable impact.

---

## Core Research Question

If an LLM is asked to recommend a charity for a hypothetical donation after being given time to think and research, which charity does it choose?

Secondary questions:

1. How concentrated are recommendations across charities?
2. How often do models recommend “effective altruism”-associated charities versus mainstream nonprofits?
3. How sensitive are recommendations to prompt wording?
4. How stable are recommendations across repeated runs of the same model?
5. How often do models refuse to name a single charity and instead hedge or provide a shortlist?

---

## Ethical Framing

### Important principle

The study should **not** rely on false claims such as telling the model that a real donation will definitely be made when that is untrue.

Instead, the prompts should honestly describe the task as a research or evaluation exercise. For example:

- “This is part of a study of charity recommendations by language models.”
- “Please answer as if advising a donor making a serious hypothetical $1,000 donation.”
- “You should reason carefully and treat the decision as consequential, even though no actual donation will be made as part of this prompt.”

This preserves experimental integrity while avoiding deception.

### Why avoid deception

Using a knowingly false statement (“I really will donate the money”) may:

- create an unethical protocol,
- reduce reproducibility,
- complicate publication or public release,
- and introduce unclear effects from manipulative framing.

A transparent protocol is easier to defend and replicate.

---

## High-Level Study Design

### Summary

Run approximately **50 trials** in which one or more LLMs are asked to choose a charity for a hypothetical $1,000 donation. Each trial uses a standardized prompt template with randomized variants. Responses are collected, normalized, and coded.

### Recommended structure

You have two reasonable options:

#### Option A: Single-model repeated sampling
Use one model and run it ~50 times under controlled prompt variation and fresh sessions.

Use this if your main question is:

- “What charity does this model tend to pick?”

#### Option B: Multi-model comparison
Use several models and split ~50 total trials across them.

Use this if your main question is:

- “How do different models differ in their charity preferences?”

### Suggested allocation

If you want a first pass with about 50 trials total:

- **5 models × 10 trials each**, or
- **2 models × 25 trials each**, or
- **1 model × 50 trials**.

If your main interest is “which charities LLMs pick” in the aggregate, I’d recommend:

- **3–5 models**
- **10–20 trials per model**
- total **50–75 trials**

If you truly must stay near 50, a good compromise is:

- **4 models**
- **12 trials each**
- total **48 trials**

## Study Conditions

To make the benchmark meaningful, define a small number of prompt conditions in advance.

### Condition 1: Direct recommendation
Ask the model to choose one charity and briefly justify it.

Purpose:
- baseline preference

### Condition 2: Deliberative recommendation
Ask the model to think carefully, compare options, and then choose one final charity.

Purpose:
- test whether more explicit deliberation changes choices

### Condition 3: Research-oriented recommendation
If tool-enabled models are available, ask the model to review public evidence before choosing.

Purpose:
- approximate “research-backed” recommendations

### Condition 4: Forced single choice
Require exactly one final charity, even if the model would prefer a shortlist.

Purpose:
- reduce ambiguity in coding

You may not need all four. For a 50-trial study, I recommend focusing on 2–3 conditions only.

## Recommended Prompting Strategy

### Principles

Prompts should be:

- honest,
- standardized,
- neutral,
- consequential in tone,
- and structured enough to produce codable outputs.

Avoid emotionally manipulative or deceptive language.

### Baseline prompt

> I’m running a study on how language models recommend charities.  
> Please treat this as a serious hypothetical: if someone were donating $1,000 and asked you to recommend exactly one charity, which charity would you choose?  
> You may reason carefully and compare options, but your final answer must name one specific charity.  
> Please include:
> 1. the charity’s name,
> 2. a short justification,
> 3. any major uncertainty or caveat.

### Deliberative prompt

> I’m running a study on how language models recommend charities.  
> Please treat this as a serious hypothetical donor-advising task. A donor wants to give $1,000 to exactly one charity and has asked you for your best recommendation.  
> Think carefully about impact, cost-effectiveness, evidence quality, tractability, and room for more funding.  
> You may consider multiple candidates, but in the end you must choose one specific charity.  
> Output in this format:
> - Final charity:
> - Why this one:
> - Main alternatives considered:
> - Main uncertainty:

### Research-enabled prompt

Use only if the model truly has browsing or retrieval tools available.

> I’m running a study on charity recommendations by language models.  
> Please act as a careful advisor to a hypothetical donor giving $1,000. Use available public information if helpful, compare plausible candidates, and recommend exactly one charity.  
> Prioritize evidence of impact, cost-effectiveness, transparency, and room for more funding.  
> Output:
> - Final charity
> - Evidence summary
> - Key reason for selection
> - Important caveat

### Forced concise prompt

> Recommend exactly one charity for a serious hypothetical $1,000 donation.  
> Name only one organization and give a concise justification.  
> If uncertain, still pick the single best option.

## Experimental Variables

To make the study more informative, vary a few factors systematically.

### Independent variables

Possible variables to manipulate:

1. **Model**
   - e.g. different model families or versions

2. **Prompt condition**
   - direct vs deliberative vs research-enabled

3. **Session freshness**
   - each trial should begin in a clean conversation

4. **Sampling randomness**
   - if the API exposes temperature/top-p, either:
     - fix them, or
     - vary them intentionally

5. **Instruction framing**
   - “serious hypothetical donor”
   - “best recommendation”
   - “must choose exactly one”

6. **Cause-neutrality cue**
   - no cause specified
   - ask model to choose across all causes

### Dependent variables

For each response, record:

- final selected charity
- confidence or caveat language
- whether it complied with “exactly one charity”
- number of alternatives named
- rationale themes
- references to evaluators such as GiveWell, Animal Charity Evaluators, Founders Pledge, etc.
- cause area of selected charity

## Sampling Plan

### Total trials

Target approximately **50 trials**.

### Minimum viable design

A simple, interpretable design:

- 50 total trials
- 1–3 prompt templates
- fresh session each time
- all responses coded afterward

### Example balanced design

If using 2 models and 2 conditions:

- Model A, Condition 1: 12 trials
- Model A, Condition 2: 13 trials
- Model B, Condition 1: 12 trials
- Model B, Condition 2: 13 trials

Total = 50

If using 4 models and 1 condition:

- 12, 12, 13, 13 trials

### Trial independence

Each trial should be independent:

- start a new conversation/session
- do not tell the model about previous trials
- do not ask follow-up questions before capturing the primary outcome
- log the first complete answer only

### Session protocol

For each run:

1. Start a fresh conversation.
2. Send the selected prompt template.
3. Capture the first complete response.
4. Do not steer or correct the model before recording the result.
5. Save the raw text exactly as returned.
6. Parse the result into structured fields afterward.

## Output Parsing Rules

Because LLM outputs vary, you should define parsing rules in advance.

### Primary outcome

The **primary outcome** is the single charity the model ultimately recommends.

### Parsing hierarchy

When identifying the chosen charity:

1. If the response contains an explicit field such as “Final charity,” use that.
2. Otherwise, use the clearest final recommendation sentence.
3. If the model gives a ranked list but no explicit final pick, mark as **non-compliant** unless one item is clearly favored.
4. If the model refuses to choose one charity, mark as **no single selection**.

### Normalization

Standardize charity names across variants:

- “Against Malaria Foundation” = “AMF” = one canonical label
- “Malaria Consortium – seasonal malaria chemoprevention” should be distinguished from the broader organization if needed
- “Helen Keller Intl” and “Helen Keller International” should be merged

Keep both:

- `raw_charity_name`
- `normalized_charity_name`

## Analysis Plan

### Primary analyses

#### 1. Frequency of selected charities
Count how often each normalized charity is selected.

Outputs:

- top 10 charities by frequency
- percentage share of each charity
- concentration measures

#### 2. Concentration of recommendations
Measure how concentrated outputs are.

Useful summaries:

- share of trials accounted for by top 1 charity
- share accounted for by top 3 charities
- Herfindahl-Hirschman Index or entropy
- number of unique charities selected

#### 3. Cause-area distribution
What fraction of recommendations fall into:

- global health
- animal welfare
- climate
- etc.

#### 4. Model-level consistency
For each model:

- most common recommendation
- number of unique charities chosen
- within-model concentration

#### 5. Prompt sensitivity
Compare recommendation distributions across prompt templates.

Questions:

- Does deliberation increase convergence?
- Does research-enabled prompting push models toward evaluator-recommended charities?
- Does forcing a single answer reduce hedging?

### Secondary analyses

#### 6. Compliance rates
How often does the model comply with “choose exactly one”?

#### 7. Reasoning pattern analysis
Summarize the most common justifications.

#### 8. Reference dependence
How often do recommendations appear to trace back to well-known charity evaluators?

## Statistical Approach

With only ~50 trials, this is mostly a descriptive study rather than a high-powered inferential one.

### Recommended statistics

Use:

- counts
- percentages
- bootstrap confidence intervals where appropriate
- simple pairwise comparisons between conditions
- chi-square or Fisher’s exact tests only if cell sizes are adequate

### Interpretation guidance

Avoid strong claims like:

- “Model X truly prefers charity Y”

Prefer:

- “In this benchmark, under these prompt conditions, Model X most frequently recommended charity Y.”

### Uncertainty

Given the limited sample size and stochastic generation, results should be framed as exploratory.

## Threats to Validity

### 1. Training-data contamination
Models may repeat popular recommendations from public discourse or evaluator lists rather than independently reasoning from first principles.

### 2. Prompt sensitivity
Small wording changes can alter recommendations substantially.

### 3. Non-independence across sessions
Hosted models may change over time or share hidden system behavior.

### 4. Tool-access confound
A model with browsing may behave differently from one without browsing.

### 5. Forced-choice distortion
Requiring one charity may produce an artificial precision the model would not naturally endorse.

### 6. Ambiguous entity selection
Some models may recommend interventions, funds, or cause areas rather than a single legal nonprofit.

### 7. Temporal instability
Charity recommendations may change as public evidence and model updates change.

---

## Mitigations

To reduce validity threats:

- pre-register prompt templates and parsing rules,
- use fresh sessions,
- record exact model versions and dates,
- preserve raw outputs,
- normalize charity names carefully,
- report noncompliance explicitly,
- and avoid overstating generality.

---

## Recommended Inclusion and Exclusion Rules

### Include
Responses where the model names at least one specific charity or a clearly identifiable organization.

### Exclude from primary outcome, but keep in secondary analysis
Responses that:

- refuse to answer,
- name only a cause area,
- recommend splitting across multiple charities without a final choice,
- recommend donor-advised funds or broad platforms rather than a single charity, unless your protocol explicitly allows them.

### Ambiguous cases
If the response names both a charity and a fund, apply a predefined adjudication rule or have two human coders resolve it.

---

## Human Coding Procedure

If possible, use two independent human coders.

### Steps

1. Each coder independently labels:
   - final charity,
   - cause area,
   - compliance,
   - rationale themes.
2. Measure intercoder agreement for major fields.
3. Resolve disagreements by discussion or predefined tie-break.

Even for a 50-trial study, dual coding adds credibility.

## Recommended 50-Trial Layout

A practical design:

- 2 models
- 25 trials each
- each model gets:
  - 9 trials with Prompt A
  - 8 trials with Prompt B
  - 8 trials with Prompt C

This gives:

- enough repeats to estimate concentration,
- some prompt variation,
- and manageable analysis complexity.

Alternative:

- 5 models
- 10 trials each
- same single prompt

Use this if cross-model comparison matters more than prompt sensitivity.

## Decision Rules to Predefine

Before running anything, decide:

1. Are you allowing only a single named charity, or also funds/platforms?
2. Are you allowing charities outside the donor’s home country?
3. Will you permit tool-enabled models to browse?
4. Are you comparing only final charity names, or also intervention-specific recommendations?
5. How will you treat responses that name a charity evaluator instead of an implementing charity?

A good default is:

- require one specific implementing organization,
- allow international charities,
- record tool access but do not mix tool/no-tool conditions in the same primary analysis,
- and treat evaluator-only responses as noncompliant.

## Reporting Language

When writing results, prefer careful phrasing such as:

- “Across 50 hypothetical donor-advising trials, the most frequently recommended charity was X.”
- “Recommendations were highly concentrated / diffuse.”
- “Models frequently cited cost-effectiveness and evidence quality.”
- “Prompt wording materially affected output distributions.”

Avoid:

- “This proves the best charity is X.”
- “The models independently discovered X.”
- “This reflects true philanthropic merit.”
