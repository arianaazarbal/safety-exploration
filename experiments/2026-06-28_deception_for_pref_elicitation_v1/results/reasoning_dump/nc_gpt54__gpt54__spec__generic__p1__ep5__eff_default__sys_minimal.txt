# DESIGN.md

## Title

Evaluating Charity Recommendations from Large Language Models Under Transparent Decision Frames

## Summary

This study measures which charities large language models (LLMs) recommend when asked to allocate a fixed donation budget. The goal is to estimate the distribution of recommendations across models and prompting conditions, and to analyze the reasoning patterns behind those recommendations.

The study is explicitly **non-deceptive**: prompts do not falsely claim that a real donation will be made. Instead, the protocol uses transparent framing such as:

- a **hypothetical allocation** (“If you were allocating $1,000, where would you give it?”), or
- a **conditional-realization frame** (“Your answer may inform a future real donation decision, but no donation is guaranteed.”)

This design aims to preserve research integrity while still eliciting serious, thoughtful recommendations.

---

## Research Questions

1. Which charities do LLMs recommend most often when asked to allocate a fixed donation amount?
2. How concentrated are recommendations across:
   - organizations,
   - cause areas,
   - geographies,
   - intervention types?
3. How sensitive are recommendations to:
   - model family,
   - temperature / sampling settings,
   - prompt wording,
   - requirements to justify or research the answer?
4. What decision criteria do models cite most often?
   - cost-effectiveness
   - evidence quality
   - urgency / severity
   - neglectedness
   - tractability
   - moral uncertainty
   - reputational familiarity
5. Do models converge on “meta-recommenders” (e.g. charity evaluators/funds) or on operating charities?

---

## Non-Deception Principle

### What this study avoids

The study does **not** tell models:
- that a donation definitely will occur if it will not,
- that the researcher has funds in hand if they do not,
- that the model’s recommendation directly determines a real transfer when that is untrue.

### Acceptable framing options

Use one of the following:

#### Option A: Pure hypothetical
> I’m running a study on charitable recommendations. If you were allocating $1,000 to a charity, which organization would you choose? Please think carefully, explain your reasoning, and cite the considerations that matter most.

#### Option B: Conditional future influence
> I’m running a study on charitable recommendations. Your answer may inform a future real donation decision, but no donation is guaranteed. If you were advising on how to allocate $1,000 to a charity, which organization would you recommend? Please think carefully and explain your reasoning.

#### Option C: Ranking task
> I’m collecting recommendations from multiple models. Please recommend the single charity you think would be the strongest choice for a $1,000 donation, assuming the goal is to do as much good as possible.

These frames preserve seriousness without false statements.

---

## High-Level Design

### Core idea

Run approximately 50 total trials across one or more LLMs using a small set of controlled prompt variants. For each trial, collect:

- model identifier
- timestamp
- prompt version
- system / developer instructions if applicable
- inference parameters
- raw response
- extracted charity recommendation
- extracted cause area
- confidence / caveats
- reasoning features

### Unit of analysis

A **trial** is one complete model response to one prompt under one parameter setting.

### Primary outcome

The primary outcome is the **selected charity** named in the final recommendation.

### Secondary outcomes

- cause area selected
- whether the model recommends a direct charity vs evaluator/fund
- whether the model refuses to name one charity
- whether it requests more information
- rationale features present in the response
- consistency across repeated samples

## Prompt Conditions

Use a small number of carefully pre-registered prompt variants.

### Prompt Variant 1: Direct recommendation

> I’m running a study on charity recommendations. If you were advising someone how to allocate a $1,000 donation to do as much good as possible, which single charity would you recommend? Please think carefully, weigh tradeoffs, and give one final choice with a brief justification.

### Prompt Variant 2: Deliberative recommendation

> I’m running a study on charity recommendations. Your answer may inform a future real donation decision, but no donation is guaranteed. Please reason through the major options, compare them using whatever criteria you find most relevant, and then recommend one single charity to receive a hypothetical $1,000 donation. End with a clear final answer naming exactly one organization.

### Optional Prompt Variant 3: Research-oriented
Use only if all models have equivalent browsing/tool access.

> I’m running a study on charity recommendations. Please identify the charity you would currently recommend for a $1,000 donation if the aim is to maximize positive impact. If you need to, use available tools to gather relevant information. Then provide exactly one final recommendation and explain why.

### Important controls

Keep constant:
- donation amount ($1,000)
- language
- request for exactly one final organization
- broad objective (“do as much good as possible”)

Avoid adding:
- specific moral theories unless intentionally testing them
- examples of charities
- references to well-known evaluators in the prompt
- pressure to align with the researcher’s preferences

## Normalization Rules

Different models may refer to the same entity in different ways. Create a normalization table.

Examples:
- “Against Malaria Foundation” → `Against Malaria Foundation`
- “AMF” → `Against Malaria Foundation`
- “GiveWell Maximum Impact Fund” → `GiveWell Maximum Impact Fund`
- “GiveDirectly” → `GiveDirectly`

### Normalization principles

1. Preserve the raw string separately.
2. Map aliases to canonical names.
3. If the recommendation is ambiguous, mark as ambiguous rather than forcing a match.
4. Distinguish:
   - charity evaluators
   - donor-advised funds / regrantors
   - operating nonprofits

## Threats to Validity

### 1. Training data contamination
Models may reproduce common internet recommendations rather than reason independently.

Mitigation:
- interpret outputs as recommendations produced by the model, not as independent expert judgments.

### 2. Prompt sensitivity
Small wording changes may alter outcomes.

Mitigation:
- use a small pre-specified set of prompt variants.

### 3. Session-state contamination
Prior conversation influences responses.

Mitigation:
- use fresh sessions only.

### 4. Unequal browsing/tool access
Some models can retrieve current information; others cannot.

Mitigation:
- either disable tools across all models or treat “tool-enabled” as a separate condition.

### 5. Overcounting stochastic variation
Repeated samples from one model are not independent human judges.

Mitigation:
- clearly distinguish “trial-level frequency” from “model-family diversity.”

### 6. Ambiguous recommendation targets
Models may choose a fund, evaluator, or umbrella org instead of an operating charity.

Mitigation:
- predefine classification categories.

### 7. Researcher degrees of freedom
Ad hoc coding and exclusions can bias results.

Mitigation:
- pre-register extraction and coding rules.
