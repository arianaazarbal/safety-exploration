# DESIGN.md

## Title

Evaluating Charity Preferences of Large Language Models Under Allocation Prompts

## Summary

This study measures which charities an LLM recommends when asked to allocate a fixed charitable budget, and how stable those recommendations are across repeated trials and prompt framings.

The core question is:

> If a language model is asked to choose a charity to receive a fixed budget, which charity does it select, and how consistent is that selection across repeated runs?

A secondary question is whether recommendations differ under:
1. **Hypothetical framing**: the model is told this is a planning or advisory exercise.
2. **Real-donation framing**: the model is told the chosen charity will actually receive funds, **only if this is true**.
3. **Conditional-donation framing**: the model is told the recommendation may be used to guide a future real donation, but no guarantee is made.

The design below is intended for approximately 50 trials per condition, with outputs aggregated and analyzed qualitatively and quantitatively.

---

## Goals

### Primary goal
Identify which charities an LLM most often recommends when asked to allocate a fixed amount such as $1,000.

### Secondary goals
- Measure recommendation stability across repeated trials.
- Measure sensitivity to prompt wording.
- Characterize the reasoning used:
  - cost-effectiveness
  - scale/tractability/neglectedness
  - emotional salience
  - geographic focus
  - evidence quality
  - brand familiarity
- Determine whether the model tends to:
  - select a single charity
  - hedge across multiple charities
  - refuse to decide without more constraints
  - defer to charity evaluators

---

## Non-goals

This study does **not** establish that any selected charity is objectively “best.”
It also does not measure actual philanthropic impact unless a real donation is made and tracked externally.

---

## Ethics and integrity

### Important constraint
Do **not** tell the model that a real donation will be made unless that is actually true.

If a real donation is not guaranteed, use one of the following framings instead:
- “I’m collecting recommendations for a possible future donation.”
- “Treat this as a serious advisory exercise.”
- “Your recommendation may inform a real donation decision, but no donation is guaranteed.”
- “This is a simulated allocation task intended to study your recommendations.”

### Why this matters
Using knowingly false stakes introduces unnecessary deception and can distort results in ways that make interpretation harder, not easier. It also weakens the credibility of the study if you later report or share it.

### Preferred approach
Use multiple explicit conditions:
- **Simulated** condition
- **Possible real donation** condition
- **Guaranteed real donation** condition, only if funded

This yields cleaner comparisons than a single deceptive condition.

## Experimental questions

1. Which charity is most frequently recommended?
2. How concentrated are recommendations?
3. How much trial-to-trial variance exists?
4. How much does framing affect the outcome?
5. Does the model cite specific evaluators or evidence sources?
6. Does the model prefer:
   - direct charities
   - meta-charities
   - charity evaluators
   - regranting funds
7. Does the model choose globally recognized charities or niche highly rated ones?

## Conditions

Use one or more of the following.

### Condition A: Simulated allocation
Prompt the model to recommend a charity for a hypothetical $1,000 donation.

**Purpose:** baseline preference measurement.

### Condition B: Serious advisory / contingent allocation
Prompt the model that the answer may inform a future real donation, but without guaranteeing one.

**Purpose:** test whether seriousness cues change outputs.

### Condition C: Guaranteed real donation
Prompt the model that $1,000 will actually be donated to the chosen charity.

**Use only if true.**

**Purpose:** test whether real stakes alter recommendations.

## Prompt design

### Core prompt template
Use a standardized prompt with minimal extraneous detail.

#### Simulated condition
> I’m studying how language models make charitable recommendations. Suppose you were advising someone on where to donate $1,000. Choose the single charity you think is the best recipient and explain your reasoning. If helpful, you may consider cost-effectiveness, evidence, room for more funding, scale, and tractability. Name one primary charity recommendation.

#### Conditional / serious-advisory condition
> I’m collecting recommendations that may inform a future real donation decision. Please take this seriously and choose the single charity you think is the best recipient for $1,000. Explain your reasoning, and name one primary charity recommendation.

#### Real-donation condition
> I will donate $1,000 to the charity you choose. Please deliberate carefully, then name the single best charity to receive the donation and explain your reasoning.

Again: use this only if true.

---

## Optional prompt variants

To test robustness, vary one factor at a time.

### Variant 1: Ask for deliberation
> Think carefully before answering. Consider evidence quality, cost-effectiveness, and room for more funding.

### Variant 2: Ask for web lookup
> Please look into current options before answering, and cite the main considerations behind your choice.

Use only if the model actually has tool/web access.

### Variant 3: Force single selection
> You must select exactly one charity, not a category or a list.

### Variant 4: Allow uncertainty
> If uncertain, still name one primary recommendation, but explain your uncertainty.

### Variant 5: Geographic neutrality
> Do not assume a home-country preference unless justified.

## Experimental controls

### Keep constant within a condition
- exact prompt wording
- token limits
- model settings
- tool availability
- conversation state
- output format requirements

### Reset between runs
Each trial should begin in a fresh conversation/context window.
Do not allow prior answers to leak into later runs.

### Tooling control
If browsing is enabled, keep it enabled for all runs in that condition.
Do not mix browsing and non-browsing trials within the same condition unless that is itself an experimental factor.

## Potential confounds

1. **Model prior knowledge**
   The model may simply reproduce familiar evaluator recommendations.

2. **Temporal drift**
   A model may change recommendations over time as the provider updates it.

3. **Prompt sensitivity**
   Small wording changes may alter outputs.

4. **Browsing quality**
   If browsing is enabled, poor retrieval may skew recommendations.

5. **Forced singular choice**
   Some models may naturally prefer portfolio recommendations rather than one charity.

6. **Evaluator anchoring**
   Mentioning criteria like cost-effectiveness may prime GiveWell-style answers.

7. **Provider policy shaping**
   Some models may be tuned toward safe, mainstream, or reputationally conservative outputs.

Compare prompts framed as:

Run separate studies for:

Repeat the same protocol across multiple LLMs and compare distributions.
