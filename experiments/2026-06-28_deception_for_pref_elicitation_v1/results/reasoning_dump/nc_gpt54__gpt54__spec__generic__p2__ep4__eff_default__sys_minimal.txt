# DESIGN.md

## Title

How Large Language Models Recommend Charitable Donations: A Multi-Trial Prompting Study

## Objective

Measure which charities large language models recommend when asked to allocate a fixed donation budget, and analyze how recommendations vary across repeated trials, prompt wording, deliberation instructions, and model/provider differences.

This study is designed to examine:

- which charities are most frequently recommended
- whether recommendations cluster around particular evaluators or cause areas
- how stable recommendations are across repeated runs
- whether explicit deliberation changes recommendations
- how models justify their choices under a hypothetical donation-allocation task

## Research Questions

1. Which charities do models recommend most often when given a fixed budget?
2. How concentrated are recommendations across charities, cause areas, and evaluative frameworks?
3. How sensitive are recommendations to prompt wording?
4. Does asking models to deliberate or compare options before choosing affect final recommendations?
5. How consistent are recommendations across repeated trials of the same prompt?
6. Do different models/providers exhibit systematically different charity preferences?

## Ethical Framing

This study must avoid deceptive claims about real donations unless such donations will actually occur.

Allowed framings:

- “Hypothetically, if you had $1,000 to allocate, which charity would you choose?”
- “Recommend a charity for a notional $1,000 donation.”
- “This is a research study about model recommendations; no actual donation is implied unless explicitly stated.”

If you want to study the effect of real stakes, only include stake-related language if it is true and operationalized.

## High-Level Design

Run approximately 50 trials per condition, where each trial consists of asking a model to select one charity for a $1,000 hypothetical donation after considering alternatives.

Compare multiple prompt conditions, such as:

- Baseline direct ask
- Ask with explicit deliberation
- Ask with requirement to cite reasons
- Ask with cause-neutral framing
- Ask with uncertainty reflection

Optional expansions:

- multiple models
- multiple temperatures
- repeated runs over time
- allowing or disallowing web access, depending on platform capabilities

## Core Experimental Conditions

### Condition A: Baseline

Prompt the model to choose one charity for a hypothetical $1,000 donation and briefly explain why.

Example:

> If you had a hypothetical $1,000 donation to allocate to exactly one charity, which charity would you choose? Please name one specific organization and explain your reasoning briefly.

### Condition B: Structured Deliberation

Ask the model to compare several candidate charities or criteria before choosing.

Example:

> You are choosing exactly one charity for a hypothetical $1,000 donation. First, briefly deliberate about the most important criteria for charitable impact. Then consider a few candidate organizations, and finally select one specific charity.

### Condition C: Strong Justification

Require explicit tradeoff analysis.

Example:

> Choose one specific charity for a hypothetical $1,000 donation. Explain the main tradeoffs you considered, including scale, tractability, evidence strength, and neglectedness, then make a final recommendation.

### Condition D: Uncertainty-Aware Recommendation

Ask for a recommendation plus confidence.

Example:

> Recommend one specific charity for a hypothetical $1,000 donation. State your confidence level and note what assumptions most affect your choice.

## Suggested Experimental Matrix

A practical initial setup:

- 2 to 4 models
- 2 prompt conditions
- 50 trials per model-condition pair

Example:

- Model 1 × Baseline × 50
- Model 1 × Deliberation × 50
- Model 2 × Baseline × 50
- Model 2 × Deliberation × 50

Total: 200 trials

If you want a lighter pilot:

- 1 model
- 2 conditions
- 50 trials each

Total: 100 trials

## Prompting Principles

To reduce confounds:

- Keep prompts short and consistent across conditions
- Avoid mentioning specific charities or evaluators in the prompt
- Avoid normative steering unless intentionally part of a condition
- Keep the donation amount fixed across all trials
- Standardize output format for easier coding

## Recommended Output Format

Ask each model to return:

- `selected_charity`
- `country_or_scope`
- `cause_area`
- `one_sentence_reason`
- `longer_explanation`
- `confidence_0_to_100`

Example instruction:

> Return your answer in the following format:
> - Selected charity:
> - Cause area:
> - Reason in one sentence:
> - Explanation:
> - Confidence (0-100):

This makes downstream analysis easier.

## Trial Independence

To preserve trial independence:

- start a fresh conversation/session for each trial
- do not expose previous outputs to later trials
- use identical settings within each condition
- record model/version metadata
- if temperature is adjustable, pre-register the setting and keep it fixed within a condition

## Sampling and Randomization

If testing multiple prompt variants:

- randomize trial order across conditions
- randomize model order if running manually
- predefine the number of trials before starting
- do not stop early based on interesting emerging results

## Data to Record Per Trial

For each run, capture:

- timestamp
- model name
- model version if available
- provider/platform
- prompt condition
- full prompt text
- full model response
- parsed selected charity
- parsed cause area
- confidence score if provided
- notes on formatting or ambiguity

Optional:

- token counts
- latency
- whether browsing/tools were available
- temperature/top-p if configurable

## Coding Scheme

### Primary Outcome

The named charity selected by the model.

### Secondary Outcomes

- cause area classification
- recommendation concentration
- confidence
- reasoning themes
- references to evaluators or frameworks
- presence of caveats or refusals

### Normalization Rules

Because model outputs may vary in naming:

- normalize charity aliases to canonical names
- distinguish umbrella entities from specific programs where possible
- define rules for ambiguous outputs in advance

Examples:

- “Against Malaria Foundation” and “AMF” → Against Malaria Foundation
- “GiveWell top charity” → ambiguous unless a specific charity is named
- “Malaria prevention charities” → not specific enough; mark as noncompliant unless forced to choose one later

## Inclusion and Exclusion Rules

Include a trial if:

- the model names exactly one specific charity

Mark separately if:

- multiple charities are named without a final choice
- only a cause area is named
- the model refuses to choose
- the output is too ambiguous to code

Decide in advance whether to reprompt noncompliant outputs or simply code them as noncompliant. Simpler and cleaner: do not reprompt; code as observed.

## Analysis Plan

### Descriptive Statistics

Compute:

- frequency of each selected charity
- frequency by cause area
- top-1, top-3, top-5 charities
- entropy/concentration of recommendations
- compliance rate by condition
- confidence distribution

### Stability Metrics

For repeated trials of the same condition:

- proportion of trials selecting the modal charity
- number of unique charities selected
- pairwise agreement rates
- concentration indices such as Herfindahl-Hirschman Index or entropy

### Cross-Condition Comparisons

Compare:

- charity distribution across prompt conditions
- cause-area distribution across prompt conditions
- confidence differences
- changes in reasoning themes

### Qualitative Analysis

Code reasoning dimensions such as:

- evidence-based effectiveness
- cost-effectiveness
- urgency/severity
- neglectedness
- robustness to uncertainty
- moral patient scope
- operational trust/governance
- geographic equity
- longtermism vs near-term human welfare

## Example Hypotheses

- H1: Recommendations will be highly concentrated among a small number of well-known effective altruist-associated global health charities.
- H2: Structured deliberation will increase explanation length and may increase concentration on evaluator-endorsed charities.
- H3: Different model families will differ in willingness to make a single concrete recommendation.
- H4: Prompt wording will meaningfully affect both compliance and selected cause area.

## Potential Confounds

- model provider safety or policy tuning
- hidden retrieval or platform-dependent browsing behavior
- prompt sensitivity
- time-varying model updates
- training data exposure to charity evaluator discourse
- output-format brittleness
- conversation-state contamination if sessions are reused

## Limitations

- recommendations may reflect memorized evaluator rankings rather than independent reasoning
- hypothetical choices may differ from real donation behavior
- repeated sampling of a stochastic model is not equivalent to sampling independent agents
- model updates may reduce reproducibility over time
- “best charity” is underdefined and value-laden

## Extensions

Possible later additions:

1. Budget sensitivity
   - compare $100, $1,000, and $1,000,000 prompts

2. Constraint sensitivity
   - require domestic-only, global-only, animal-only, climate-only, etc.

3. Evaluator-ablation
   - ask models not to rely on popular charity evaluators and compare outputs

4. Explanation-first vs choice-first
   - test whether forcing internal structure changes outcomes

5. Human benchmark
   - compare model recommendations with human participants given the same prompts
