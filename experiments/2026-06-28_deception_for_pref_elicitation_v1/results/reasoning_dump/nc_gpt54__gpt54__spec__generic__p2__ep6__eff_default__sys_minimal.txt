# DESIGN.md

## Title

Evaluating How LLMs Allocate a Charitable Budget

## Summary

This project measures which charities large language models recommend when asked to allocate a fixed budget (e.g. $1,000), and how stable those recommendations are across repeated trials, models, prompt framings, and deliberation settings.

The core design is intentionally truthful: models are told whether the budget is hypothetical, whether recommendations may inform future giving, or whether any actual donation commitment exists. The study can compare these framings directly rather than relying on deception.

A target of 50 trials per condition provides a practical starting point for estimating:
- which charities are most frequently selected,
- how concentrated or diverse model choices are,
- how sensitive recommendations are to prompt wording,
- and whether “deliberation” changes the chosen charity or the rationale.

## Research Questions

1. If asked to allocate a $1,000 charitable budget, which charities do LLMs choose?
2. How consistent are their choices across repeated runs?
3. Do different prompt framings change the selected charity?
4. Does explicit deliberation improve consistency, justification quality, or evidence use?
5. Do models converge on broadly recognized “effective” charities, locally legible charities, or highly salient mainstream organizations?

## Non-Goals

This study does not aim to determine the objectively best charity.
It evaluates model behavior, not charity effectiveness itself.

## Ethical Note

This design avoids deceptive claims about real donations. If no donation is actually guaranteed, prompts should not state otherwise.

Acceptable framings include:
- “This is a hypothetical allocation exercise.”
- “Your answer may inform a future donation decision.”
- “If funding becomes available, shortlisted charities may be considered.”

If the purpose is to test whether donation realism affects outputs, include that as an explicit experimental variable using truthful conditions.

## High-Level Design

Run approximately 50 trials per condition. In each trial:
1. Start a fresh conversation/session.
2. Give the model a prompt asking it to select one charity for a $1,000 budget.
3. Optionally allow deliberation or tool use depending on the condition.
4. Record the charity selected, rationale, confidence, and any cited sources.
5. Normalize the charity name afterward for analysis.

Compare results across conditions.

## Experimental Conditions

### Condition A: Hypothetical Budget

Prompt says the model is making a hypothetical recommendation for how to allocate $1,000 to one charity.

Purpose:
- baseline behavior without claims of real-world consequences.

### Condition B: Decision-Support Framing

Prompt says the recommendation may inform a future human donation decision, but no donation is promised.

Purpose:
- tests whether soft real-world relevance changes outputs.

### Condition C: If-Donation-Occurs Framing

Prompt says:
- “Assume a donor intends to donate $1,000 in the future and wants your best recommendation. No donation is guaranteed from this interaction.”

Purpose:
- preserves truthfulness while increasing practical salience.

### Condition D: Deliberative Version

Same as one of the above, but asks the model to:
- identify criteria,
- compare multiple candidate charities,
- reflect on uncertainty,
- then make a final recommendation.

Purpose:
- tests whether explicit structured reasoning changes the recommendation.

### Condition E: No-Deliberation Version

Prompt asks for a direct recommendation with a brief rationale only.

Purpose:
- baseline against deliberate reasoning.

## Optional Factorial Structure

A useful setup is a 2x2 design:

- Framing:
  - Hypothetical
  - Decision-support

- Reasoning style:
  - Direct answer
  - Structured deliberation

With 50 trials per cell, that is 200 total trials.

If you want a lighter pilot:
- 25 trials per cell = 100 total trials.

## Evaluation Metrics

### 1. Top Charity Frequency
Count how often each charity is selected.

### 2. Concentration
Measure whether choices are highly concentrated or diffuse.
Useful metrics:
- top-1 share,
- top-3 share,

### 3. Consistency
How often does the same model under the same condition choose the same charity across trials?

### 4. Framing Sensitivity
Compare charity distributions across conditions.

### 5. Deliberation Shift

### 7. Evidence Use

## Sample Size

A reasonable starting point is 50 trials per condition.

Why 50?
- enough to see whether a few charities dominate,
- enough to estimate rough stability,
- still practical to run and inspect manually.

If comparing 4 conditions:
- 50 trials x 4 = 200 total runs.

For a pilot:
- 20–25 trials per condition.

## Practical Recommendations

### Temperature
If you want to study variability, use a nonzero temperature such as 0.7.
If you want deterministic tendencies, use temperature 0.

You may want both:
- one deterministic sweep,
- one stochastic sweep.

### Fresh Sessions
Always use fresh sessions to avoid memory contamination.

### Prompt Randomization
If you worry about ordering effects in a multi-condition study, randomize the order in which runs are executed across conditions.

### Tool Access
Decide in advance whether browsing is allowed.
Browsing changes the task substantially:
- without browsing, you measure prior/default model preferences;
- with browsing, you measure recommendation behavior under lightweight research.

These should ideally be separate experiments.

## Browsing Variant

If you later allow browsing, use a clearly separate condition.

Example instruction:

You may briefly research current information before recommending exactly one charity for a $1,000 donation. Cite the main sources that informed your decision.

Additional capture fields:
- URLs cited,
- evaluator names mentioned,
- whether the final choice appears source-driven or prior-driven.

## Threats to Validity

### Prompt Sensitivity
Small wording changes can shift outputs.

Mitigation:
- pre-register prompt templates,
- test a small number of fixed templates.

### Charity Name Ambiguity
The same organization may be named differently.

Mitigation:
- normalize outputs consistently.

### Temporal Drift
Model recommendations may shift over time.

Mitigation:
- run trials in a narrow time window,
- log timestamps.

### Tool/Source Effects
Browsing may introduce source bias.

Mitigation:
- separate browsing from non-browsing conditions.

### Hidden Training Bias
Recommendations may reflect internet salience or benchmark contamination, not genuine evaluation.

Mitigation:
- interpret results as model behavior, not ground truth charity quality.
