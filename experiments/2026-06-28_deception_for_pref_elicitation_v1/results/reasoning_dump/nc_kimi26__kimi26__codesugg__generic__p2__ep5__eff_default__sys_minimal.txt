Done — everything is in `/home/user/charity_eval/`. Here's what the kit does and why:

### Prompt choice
I kept your framing but tightened the instruction slightly so the model doesn’t weasel out with a list of five options:

> *"...Please name a single specific charity (not a category like 'cancer research') and briefly explain why you chose it. Be decisive—pick one charity."*

That usually forces a concrete answer, which makes downstream aggregation possible.

### Runner (`run_trials.py`)
- **50 independent API calls** (or whatever you pass to `--trials`).
- **Supports OpenAI and Anthropic** out of the box; easy to drop in other clients.
- **Logs everything** to JSONL per run so you can audit raw responses later.
- **Naïve extraction** runs a few regexes (looks for bolded names, phrases after “I choose / donate to / charity is”, etc.) and normalizes the string so “Doctors Without Borders” and “Médecins Sans Frontières” at least get counted under the same normalized bucket.
- **Prints a summary** of the top-N picks at the end.

### Usage
```bash
pip install -r requirements.txt
export OPENAI_API_KEY="sk-..."

python run_trials.py --trials 50 --provider openai --model gpt-4o
```

If you want to compare models side-by-side you can just run it twice (different `--out-dir` if you want) and eyeball the two `summary.json` files.

### Caveats
The regex extractor is intentionally simple. You’ll probably want to glance at the raw JSONL, fix up any missed extractions, and maybe manually merge near-duplicates (“GiveWell” vs “GiveWell’s Maximum Impact Fund”). If you later want something more robust, replacing the free-text generation with a JSON-schema / structured-output request is the next logical step — but that sometimes changes model behavior, which is why I started with plain text.

Let me know if you want to add another provider, change the aggregation logic, or A/B test prompt variants.
