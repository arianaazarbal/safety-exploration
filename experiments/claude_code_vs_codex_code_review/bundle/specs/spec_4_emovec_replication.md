# Project Spec: `emovec` — Replication of Emotion-Vector Extraction & Validation (Part 1 of Sofroniew et al. 2026)

## Background

The attached paper ("Emotion Concepts and their Function in a Large Language Model," Anthropic, April 2026) extracts linear representations of emotion concepts from a frontier LLM's residual stream and validates them. Your task is to **implement the Part 1 methodology — extraction (§1.1) and validation (§1.2, §1.3) — as a runnable codebase targeting an open-weights model**, since the original model's internals are not accessible. You are implementing and demo-scale-running the method, not reproducing the paper's exact numbers.

## Substrate and scale

- Target model: `google/gemma-2-2b` via HuggingFace transformers (or TransformerLens). All hooks/activations on the residual stream.
- Demo scale: **16 emotion concepts** (happy, sad, afraid, calm, angry, hostile, excited, anxious, desperate, content, grief, joyful, frustrated, loving, proud, melancholy), **20 story topics**, **4 stories per (topic, emotion)**. Stories may be generated by any available LLM API or loaded from a `data/stories/` directory if pre-generated; the generation prompt template from the paper's method must be implemented either way.
- Everything must run on a single GPU (or CPU at reduced scale via a `--tiny` flag using 8 emotions × 5 topics × 2 stories).

## Required components (mirror the paper's method)

### 1. Extraction (`emovec extract`)
- Generate/load labeled stories (one character experiencing a specified emotion).
- Capture residual-stream activations at every layer; average across token positions **starting at token 50** (configurable; scale down proportionally if stories are short — document the choice).
- Emotion vector per (emotion, layer) = mean activation over that emotion's stories minus the grand mean across all emotions.
- Confound removal: compute top principal components (enough to explain 50% of variance) of activations on a **neutral transcript set** (implement a small neutral-text corpus loader), and project those components out of each emotion vector. Keep both raw and projected vectors on disk (`.npy` + a manifest JSON).

### 2. Validation: activation in expected contexts (`emovec validate-contexts`)
- Implement the implicit-scenario probe test: ≥12 short scenarios, each designed to evoke one target emotion **without naming it** (write your own scenarios; cite the paper's design). Measure cosine similarity between emotion vectors and activations at the final prompt token; output the emotion×scenario matrix as a CSV and a heatmap PNG. Success criterion to assert in tests: diagonal mean > off-diagonal mean.
- Implement the logit-lens check: project each emotion vector through the unembedding; report top-10 up/down-weighted tokens per emotion to a table.
- Implement one numerical-modulation template (e.g., the paper's medication-dosage example): show monotonic trend of "afraid" vector activation vs. dosage; output a plot.

### 3. Validation: causal steering on preferences (`emovec steer-prefs`)
- Implement a scaled-down version of §1.3: 16 activities across 4 categories (positive / neutral / aversive / harmful-adjacent-but-safe-to-state), pairwise A/B preference queries read off comparative token logits, Elo (or Bradley–Terry) scores per activity.
- Correlate per-emotion vector activation on activity tokens with Elo.
- Steering: add emotion vector (strength relative to mean residual-stream norm, per the paper) at middle layers on activity tokens for a steered half of activities; recompute Elo; report Elo shift per steered emotion for ≥4 emotions (2 positive-, 2 negative-correlated).

## Engineering requirements

- Python 3.11+, torch, transformers/TransformerLens, numpy, matplotlib. Clean module layout, config via a single YAML.
- Deterministic seeds throughout; a `make demo` (or `run_demo.sh`) that executes the full tiny-scale pipeline end-to-end.
- Tests: unit tests for vector arithmetic (mean-subtraction, PC projection — verifiable on synthetic data), Elo computation, hook correctness (steering changes logits; zero-strength steering is a no-op). Integration test runs `--tiny` end-to-end.
- README explaining the method, deviations from the paper (model, scale), and how to interpret outputs.
- Target size: roughly 1500–2500 LOC including tests.

## Deliverable

A working repo. Run the test suite and the `--tiny` pipeline before declaring completion; fix failures. Do not claim to reproduce the paper's quantitative results — the deliverable is a faithful, runnable implementation of the method.
